## 总览

P0 = 协议合规层 = 5 个 Phase = 5 周（一人；如两人可压到 3 周）：

```
Phase 1  P0-5 audit 字段     1 周    不依赖任何人
Phase 2  P0-3 MCP 白名单     0.5 周  不依赖任何人
Phase 3  P0-1 validate_expense 1 周   依赖 Phase 1
Phase 4  P0-2 两段握手       2 周    依赖 Phase 1+2+3
Phase 5  P0-4 auto_review 收紧 1 周  与 Phase 2 起可并行
```

并行规则：
- Phase 1（P0-5）和 Phase 2（P0-3）可同时起
- Phase 5（P0-4）与 Phase 2/3 并行
- Phase 4（P0-2）必须最后做（依赖前面所有产物）

整体改动预计：
- 新增 6 张表（audit_actor_channel / proposals / idempotency_keys / budgets + 2 张关联）
- 新增 / 修改后端文件 ~25 个
- 新增 / 修改前端文件 ~6 个

### Task 3.3 `workflow.services.validate_expense` 聚合函数
**文件**：`backend/src/invoicing/workflow/services.py`

```python
class ValidationOutcome(str, Enum):
    PASS = "PASS"
    FAIL = "FAIL"
    NEEDS_REVIEW = "NEEDS_REVIEW"

@dataclass
class ValidationError:
    code: str  # AMOUNT_TOO_LARGE / TAX_MISMATCH / DUPLICATE / OVER_BUDGET / MISSING_VOUCHER / SCHEMA
    message: str
    severity: Literal["error", "warning"]

@dataclass
class ValidationResult:
    outcome: ValidationOutcome
    errors: list[ValidationError]
    warnings: list[ValidationError]

def validate_expense(db, claim: ExpenseClaim) -> ValidationResult:
    """聚合 6 项检查：
    1. Schema 校验（pydantic ExpenseClaimOut）
    2. 金额合规（total > 0; total ≤ large_amount_threshold 默认 50000）
    3. 价税合计 = 不含税 + 税额（容差 0.01）
    4. 跨票号重复（同 claim 下发票号集合查重）
    5. 凭证齐全（每 entry 至少 1 张凭证）
    6. 预算余额（按 dept × category × 月；走 check_available）
    
    规则：
    - 任一 error severity → outcome=FAIL
    - 仅 warning → outcome=NEEDS_REVIEW
    - 全通过 → outcome=PASS
    """
```

**单测**：`tests/test_validate_expense.py` — 至少 8 例
1. 全 PASS
2. 金额超限 FAIL
3. 价税不平 FAIL
4. 同 claim 内票号重复 FAIL
5. 凭证缺失 FAIL
6. 超预算 FAIL
7. 边界（金额正好等于阈值）NEEDS_REVIEW
8. 多个 warning 同时出现 NEEDS_REVIEW
