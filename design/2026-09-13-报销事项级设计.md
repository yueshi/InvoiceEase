# 报销场景化：事项级明细（按事项关联发票/单据）

日期：2026-09-13 ｜ 状态：待确认 ｜ 依赖：[报销 P0 设计](./2026-09-13-发票易报销功能设计.md)（已实施）

## 一、调研：为什么需要「事项」这一层

主流与实务口径均要求报销单**逐项列明**，而不是一堆票的集合：

| 来源 | 明细行要求 |
|------|-----------|
| 报销单填写规范（金蝶等） | 费用**发生日期**、**费用类型**、金额、**费用说明（事由）**、项目/客户编号 |
| 企业报销模板 | 序号、日期、费用类别、**事项说明**、**票据/订单号**、金额、**是否超标**、审核结论 |
| 差旅场景 | 独立**行程明细表**：行程单号/人数/路程/时间/**住宿天数/在途天数**；附件需出差申请、行程证明 |
| 采购场景 | **三单匹配**：订单 + 入库单 + 发票自动比对；需采购申请、合同、验收证明 |
| 招待场景 | 明细须填**招待对象、人数、事由**；往往要求"三单"（票据、公函、接待清单）齐备 |
| 通用要求 | "一事一报、一单一清"；事由需写清背景/目的/对象/成果；票据日期需与业务逻辑连贯 |

**结论**：当前 P0 的「报销单 → 凭证」两层太扁——一张票挂了事由，但**多个事项混在一张单里无法分别说明**（如出差单里的机票/住宿/市内交通各有行程与事由）。需要引入**事项（entry）**层。

## 二、目标结构（三层）

```
expense_claims 报销单（报销人/汇总金额/状态/审批）
   └── expense_entries 事项（费用发生日期/类型/事由/场景字段/金额）
           └── expense_items 凭证关联（发票 | 银行回单 | 人工凭证）
```

- **事项金额 = 其凭证合计**（自动计算，不可手改）→ 报销单金额 = 各事项合计
- **事项必须关联 ≥1 凭证**（发票/回单/人工凭证三类之一，人工凭证即无票支出的合规凭证）
- 保留 P0 的**一票一报**（DB 部分唯一索引不变，仍约束 active 明细的发票/回单唯一）

## 三、场景扩展字段（`entry.scene_fields` JSON，按类型校验）

| entry_type | 场景字段 | 必填校验 | 调研依据 |
|-----------|---------|---------|---------|
| `travel` 差旅 | from_city / to_city / start_date / end_date / days | 起止日期 + 城市 | 行程明细表 |
| `procurement` 采购 | supplier / contract_no / order_no / acceptance_no | 供应商（其余记"要素不全"提示） | 三单匹配 |
| `entertainment` 招待 | guests（招待对象）/ headcount（人数） | 招待对象 + 人数 | 招待三单 |
| `office` 办公 | — | — | — |
| `other` 其他 | — | — | — |

**不做的（YAGNI，留 P1/P2）**：差旅标准与超标判定（费控）、订单/入库单系统对接、三单自动匹配。

## 四、校验规则

1. 事项类型合法（五类）；场景必填项缺失 → 拒绝；建议项缺失 → 标记提示（不阻断）
2. 事项金额 = 凭证合计；报销单金额 = 事项合计（提交时重算）
3. **票据日期与事项日期一致性提示**：凭证日期落在事项日期区间外 → 提示（不阻断，跨月票据常见）
4. 提交前置：每个事项 ≥1 凭证；至少一个事项
5. 一票一报、验真门槛、员工范围、无票支出凭证要素 —— 全部沿用 P0 规则

## 五、兼容迁移（已实施 P0 的单据）

现有 `expense_items` 无事项归属 → 迁移时**按 (claim_id, expense_type) 分组**生成默认事项
（标题 = 费用类型名，如「其他」），把该组凭证挂到事项下，保证历史单据可读；
迁移后 `expense_items.entry_id` 置 NOT NULL。

## 六、接口与界面

**API**
- `POST /api/v1/expenses/{id}/entries`（建事项，带类型/日期/事由/场景字段）
- `PATCH /api/v1/expenses/{id}/entries/{entry_id}`、`DELETE .../{entry_id}`
- 凭证加入端点增加 `entry_id`（`POST /expenses/{id}/entries/{entry_id}/invoices|receipts|vouchers`）
- `GET /expenses/{id}` 返回按事项分组的结构（claim → entries[] → items[]）

**MCP（Agent 侧）**
- `expense_add_entry(claim_id, entry_type, title, occurred_on, scene_fields...)`
- `expense_add_invoices(claim_id, entry_id, invoice_numbers, ...)`（加 entry_id 参数）
- `expense_list` / 详情返回事项摘要（便于 Agent 汇报"机票 2 张 1,240 元、住宿 3 晚 1,580 元"）

**前端（我的报销详情）**
- 详情页改为**按事项折叠分组**：事项头显示类型/日期/事由/场景字段/金额；展开显示其凭证列表与「加凭证」按钮
- 新建事项表单**按类型动态显示场景字段**（差旅显示起止城市与日期、招待显示对象与人数…）
