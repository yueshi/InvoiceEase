# 回单原件定位（R1.2）：页码 + 锚点高亮

日期：2026-09-12 ｜ 状态：已实施

## 问题

一份 PDF 含多张回单（实测 6 页 18 张），点「原件」打开的是整份 PDF 第 1 页，
人工核对要逐页翻找。

## 存储（bank_receipts 两列）

| 列 | 说明 |
|----|------|
| `page_no` int | 页码（列表显示「定位 P3」、排序/筛选）；页码的唯一真相 |
| `anchor` JSON | `{"bbox":[x0,y0,x1,y1], "text":"…", "v":1}`；bbox 为**归一化**坐标（除以页宽高，原点**左下**），与渲染尺寸/DPI 解耦 |

设计取舍：
- bbox 不存像素、不存页宽高（渲染时必然解析 PDF，当场可得）——避免冗余真相
- `text` 存锚点串（规范化），坐标不可用时供搜索兜底、原件替换时可校验
- `v` = 算法版本，便于将来重算（`WHERE anchor->>'v' < 2`）

## 定位算法（parse/receipt.py + pdf_text_parser.py）

1. **逐页分块**：`extract_pdf_pages` 逐页取文本，页内按免责声明行切块 → 每行带页码
2. **锚点串选择**（`anchor_token`）：① 带标签的流水号/税票号码（最长者）→
   ② 金额（手续费/利息无流水号版式）→ ③ 剔除本司账号后的最长字母数字串。
   *教训：不能直接取最长数字串——那是本司账号，页内每张回单都出现，会定位错位*
3. **坐标定位**（`PdfiumLocator`）：PDFium 为**每个字符**重建坐标框（pypdf 的矩阵法
   在本类回单上仅覆盖约半数片段，实测 12/18）；候选串按序搜索，**词边界校验**
   （拒绝嵌在长数字内部的匹配——短日期串曾误命中流水号）
4. **区域切分**：同页多张按锚点 y 的**中点**切带，首/尾延伸至页边
5. 定位失败 → `bbox=None`，前端降级为「仅页码 + 整页提示」

## 渲染与前端

- `GET /receipts/{id}/page.png?dpi=`：pypdfium2 渲染该页，按 `file_hash+页+DPI`
  **缓存到存储**（派生数据）；渲染库缺失返回 501
- 前端「定位」按钮 → 弹窗：页面图 + CSS 覆盖层（归一化 bbox → top 需按
  `1-y1` 翻转）；501 或 bbox 为空时降级为「打开原 PDF 第 N 页#page=N」

## 验证

- 真实建行 PDF：18/18 定位成功；用 `PDFium.get_text_bounded` 读取每个 bbox
  区域，**18/18 区域包含本张金额**（自动化校验，见提交说明）
- 页面渲染 0.53s，缓存命中 0.008s
- 回填脚本 `backend/scripts/backfill_receipt_anchors.py`（幂等，按 file_hash 重解析，
  只写定位列）已对存量 18 条执行
