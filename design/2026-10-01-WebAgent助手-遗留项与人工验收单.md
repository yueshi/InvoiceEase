2. 静态路径（后端 LLM 关闭时）在 UI 中的分片打字机效果
3. 真实 LLM 路径：`invoice_list` 工具 chip「运行中 → 完成 · xxms」渲染；中文回答排版

6. 生成中点「停止」→ 流停、保留已收内容（服务端为非即时停止，见二.2）

8. 流式中新建会话 / 切会话的回归行为

## 二、真机冒烟发现并如实记录的 3 项（未改代码）

1. **ScopeDenied 文案面向 MCP 令牌**：Web 用户会看到「请在『我的令牌』中重新签发」——权限守门本身正确，文案错位。后续可在 `mcp/identity.py` 按 `principal.source=="agent"` 分支文案（共享模块，本波未动）。
2. **「停止」非即时**：客户端断连后当前轮仍会跑完（轮界检查 cancel_event；T14 实测断连后 6081ms 才落库）。属计划注明的设计上限；断连仍落库是**期望行为**。
3. 模型可能对同一问题连开多次同类工具（如 `invoice_list` 连查两次）。非缺陷，prompt 可再优化。

## 三、已知上限（评审建议记录）

| 项 | 说明 | 触发改进的时机 |
|---|---|---|
| 工具 manifest 全量进 prompt | 38 个工具 schema 每轮注入（约万级 token/轮）；「按 scope 懒披露」已延后 | 先量实际 token 占比再决定 |
| 「停止」非即时 | 仅轮界检查 cancel_event | 需要秒级中止时改为流内检查 |
| 工具 chip 无 call id | 同批并行同名调用（两次 `invoice_list`）会状态错配 | 动 matcher 时帧加 call id + 补 4 行用例 |
| SQLite 下并行工具写竞争 | 本地开发模式；生产 PG 无碍 | 切 PG 后自然消解 |
| AGENT_INTERNAL 异常路径 `assistant_reply` 不落库 | 已流式展示的半截文本重开会话后丢失（评审 Out-of-Scope 观察） | 需要语义完整时补 |

## 四、待人类决策（设计 owner）

**写操作确认清单范围**：system prompt 目前要求 8 个高危工具先复述确认（`expense_submit / expense_approve / invoice_delete / invoice_unblock / invoice_update / red_invoice_link / bank_account_delete / company_info_delete`）；另有 6 个同样写库但免确认（`receipt_pair / expense_add_receipt / expense_add_voucher / company_info_save / bank_account_save / sales_invoice_import`）。要么明确「仅高危破坏性操作需确认」判据并写进 prompt，要么扩清单。**不要**引入 UI 弹框协议（设计刻意 YAGNI）。
