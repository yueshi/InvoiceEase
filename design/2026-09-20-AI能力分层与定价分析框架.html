〇、怎么用这个框架（三条使用纪律）

  1. 按「每任务成本」而非每百万 token 单价做预算——同一 agent 工作负载实测月成本在不同模型间差 29 倍（约 $370 vs $10,725），且输出/推理 token 占账单 60% 以上，单价表会系统性误导决策；
  2. 每层至少看 4 个参与者再下结论——每层列国际大厂 / 国内厂商 / 开源 / 垂直玩家四类，任一单点案例（包括我们自己的 PoC）不得直接外推；
  3. 价格锚点保质期约半年——下方数字为 2026-09 快照且含促销价与峰谷计价，采购前必须复核官方价页。

  • API 侧价格与 L2 重叠，差异化不在单价而在结构化输出合规率

L4 规则：无市场价格。它就是「0 元/张且 100% 准确」的基准线。

2.1 一张票的模型成本账（校准直觉用）

按「每张票 3k 输入 + 0.5k 输出 token」（走 LLM 的票）：

通道月 500 张的成本
qwen3.7-flash（0.03/0.13）约 $0.08
DeepSeek V4 Flash 谷价（0.22/0.66）约 $0.50
Gemini 3.8 Flash 促销价（0.75/3.75）约 $2.06
旗舰档（如 Opus 5，5/25）约 $13.75
结论：单企业月几百张票量级下，L2 之间选谁的价格差是「几毛钱 vs 十几块钱」——模型成本相对盒子/订阅定价占比 <1%。因此：不要按 token 定价，也不要把「省 token」当架构目标；选型由准确率、合规（离线）、工程稳定性主导；真正吃成本的是部署与运维（人肉陪跑），不是推理。

三、定价逻辑：四层的定价权与我们的位置

L1 能力上限定价（贵，被算力成本压）
        ▲ 约束
L2 商品化定价（弱定价权，价格战）      ← 我们买它的「执行」
        ▲ 约束
L3 阶段性定价（架构差异窗口，三重压力） ← 我们自研「决策」的地方
        ▲ 被压顶（记住这个方向）
L4 零定价（0元基准，压低上面三层天花板） ← 我们的毛利与确定性来源
  1. L4 越厚，产品越稳：XML 直解与规则校验是 0 元且 100% 准确的路径；如果 80% 的票要过模型，成本结构没差多少，但确定性变差——坏处不在钱在风险。
  2. L3 的窗口期是「现在」，但护城河必须换：架构差异会被云厂商复刻、小模型追平（09-17 调研已有 2B 蒸馏绕过结构门槛的路径）。能守住的是垂直校准数据——改判埋点积累的「什么票会判错、人工怎么改」是云厂商拿不到的。
  3. 对客定价锚在「替代了什么人力」，不在「用了什么模型」：财务 3-5 分钟/张的人工成本是定价锚（PoC 复盘指标口径）。对外叙事里不要出现 token/模型分层，客户买的是「票进去、合规出来」。

五、当前阶段（种子 PoC → 盒子）的行动与重估触发

5.1 现在做什么

动作理由
L2 保持「可替换」：LLM 走 OpenAI 兼容层（已实现），不写死供应商价格战环境下半年一换是常态，¥0.80～$3.75/百万的档位差异随时翻转
L4 持续加厚：归类规则命中率、校验规则覆盖零成本 + 零风险 + 压住高层定价，三重收益
L3 只做「校准」不做「模型」：改判埋点数据积累与阈值调优护城河在数据；模型能力等 09-17 调研的空白实验补完再说
盒子内 L3：先跑通「小模型初筛 + 规则门控 + 人工兜底」，CPU-only 实测优先09-17 调研明确：CPU-only 是证据空白，不可默认可行
L1 当前不接月 500 张量级用不到；真遇到极难件，拒收 + 人工比调旗舰便宜两个数量级

5.2 何时重估（触发条件）

  1. L2 价格再降 5 倍（如 flash 档跌到 $0.01/百万级）→ 重估「盒子内自托管」的 TCO 优势是否还存在（可能云端直连更划算）
  2. 开源小模型在中文数电票上的实测精度达标（自建评测集上关键字段 ≥ 人工复核门槛）→ L3 自托管窗口打开，盒子方案成立
  3. 云厂商复刻结构化决策（把「票据→结构化+置信度」做成标准 API 且带合规资质）→ L3 自研价值重估，护城河退回改判数据与流程
  4. 旗舰能力全面受限通道化 → 「能力上限」叙事的商业含义变化，对盒子（本地算力）反而是利好
  5. 法规版本变更（发票/税前扣除规则）→ L4 全面回归，与模型无关但优先级最高
