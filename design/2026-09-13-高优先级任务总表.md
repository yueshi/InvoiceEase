## P1.5 — MCP 身份与权限（本轮新开工作流，阶段 1 已完成）

> 详细设计：[MCP 身份与权限设计](./2026-09-13-MCP身份与权限设计.md)

**问题**：MCP 通道原为「一个静态 token = 管理员通道」——无用户身份、无角色校验、
审计 12 处 `channel="mcp"` 多数不带 `user_id`。Web 通道 RBAC 达标、MCP 不达标，
而 FRD §3.5.2/§380 要求权限隔离、§3.4 又把 MCP 列为核心集成方式。

| ID | 任务 | 状态 | 提交 |
|----|------|------|------|
| **M1** | `mcp_tokens` 表 + `Principal`/`requires` + `MCPTokenVerifier`（含 legacy 零中断回退） | ✅ 完成 | `400c4f5` |
| **M2** | 装配 SDK 认证栈、删除自研 `MCPAuthMiddleware` | ✅ 完成 | `98ad87d` |
| **M3** | 36 工具全部改用真实身份 + 工具级 scope（13 个 scope） | ✅ 完成 | `eae4844`+`68a7168` |
| **M4** | 审计补主体（user_id + token_id + tenant_id） | ✅ 完成 | `68a7168` |
| **M5** | 令牌管理 API + Web「我的令牌」页面（自助签发/撤销/代发） | ✅ 完成 | `400c4f5`+`91ccd2f` |
| **M6** | **阶段 2：OAuth 2.1 Resource Server**（对接企业 IdP） | ⏸ **待触发** | — |

**M6 的启动触发器**（满足任一即启动，详见设计 §6.2）：
① 客户采购清单出现「统一身份认证」 ② 接入的 Agent 平台要求标准 OAuth
③ 令牌运维出过事（离职未撤致越权） ④ 多租户/代账（E3）立项

**明确不做**：自签 JWT 充当中庸方案（半只脚踏进 OAuth，拿到成本没拿到收益，且不满足规范）。

**副产品（顺带修掉的）**：测试套件 bcrypt cost 可配（`INVOICING_PASSWORD_HASH_ROUNDS`），
conftest 设 4 → **全量 312s → 91s（3.4×）**，此后每次回归都受益。
