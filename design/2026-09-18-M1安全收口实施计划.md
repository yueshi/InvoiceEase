## T1 生产形态 fail-fast + 新增自检项（核心）

**改法：**
1. `config.py` 新增 `invoicing_env: str = "dev"`（`dev | production`），并加注释：production 即「对外服务形态」
2. `ops/checks.py`：
   - `run_startup_checks` 的阻断判定改为 `strict = settings.startup_checks_strict or settings.invoicing_env == "production"`（一行，production 无条件按 strict 执行）
   - `check_default_secrets`：production 下命中默认值一律 fail（dev 维持 warn）——现实现已按 strict 分级，随上一条自动生效，仅需文案注明
3. 新增自检项 `check_inbox_dir`：`invoicing_env == "production"` 且 `workbuddy_inbox_dir` 为空 → **fail**（MCP 可读任意路径，生产必须收口）；dev 下 info（当前行为不变）
4. 新增自检项 `check_offline_llm`：新增 `offline_deploy: bool = False`，为 true 且 `llm_enabled` 且 `llm_base_url` 主机非私网/localhost（10.x / 192.168.x / 172.16-31.x / localhost）→ **fail**（R6：离线部署禁止数据出内网）
5. `_CHECKS` 注册两项；`_DEFAULT_SECRETS` 不动（`mcp_token` 改空默认后见 T3）

**验收：** 新增测试——production + 弱 jwt_secret → `run_startup_checks` 抛 RuntimeError；production + inbox_dir 空 → fail；`offline_deploy=true` + 云端 LLM → fail；dev 行为与现状逐项一致。

## T2 CORS / TrustedHost 中间件

**改法：** `main.py` `create_app` 挂 `CORSMiddleware`（`allow_origins=cors_origins` 逗号分列，空串=不开跨域，维持同源）与 `TrustedHostMiddleware`（`allowed_hosts` 逗号分列，空串=不挂中间件）。新增设置 `cors_origins: str = ""`、`allowed_hosts: str = ""`。

**边界：** 当前 dev 走 vite 代理（同源），默认零行为变化；值留生产部署时配。

**验收：** 测试——空配置下响应无 CORS 头；配置 origin 后带 `access-control-allow-origin`。

## T3 legacy MCP token 默认关闭

**改法：** `config.py:22` `mcp_token` 默认值 `"change-me"` → `""`（通道关闭）；`.env.example` 注释同步「留空=关闭，兼容旧 WorkBuddy 时才显式配置」。本机 `.env` 已显式配置该值，不受影响。

**验收：** 测试——默认配置下 legacy 令牌 401、个人令牌正常；显式配置后 legacy 通道行为不变（存量测试保障）。

## 不做什么（边界）

- 不做 HTTPS/TLS、部署物（M2）；不做 PG/Redis（M2）
- 限流不做分布式（当前单进程部署形态成立， ponytail 注释留升级路径）

- admin 首启强制改密不在本批（`admin_password` 弱值已由 T1 production fail-fast 覆盖）
