# 小模型（1.5B–2B）离线发票提取可行性调研

> 日期：2026-09-17　状态：调研报告（未立项）
> 方法：deep-research 多代理工作流——6 个检索角度 × 27 个来源 → 135 条论断 → 25 条进入对抗验证（每条 3 票）→ 15 条确认 / 10 条被否 → 合成 10 条发现
> 成本：110 个 agent 调用
> 关联：`frd/InvoiceEase-frd-v0.1.txt`（分级路由解析）、`CLAUDE.md`（合规硬约束：支持纯离线部署，数据不出企业内网）

## 0. 一句话结论

**1.5B–2B 小模型不能替代云端大模型做中文发票的最终判定，但可以承担「识别 + 首轮字段抽取 + 初筛路由」**——前提是做任务专用微调或约束解码，并配确定性校验门控。工程上决定成败的不是模型尺寸而是**管线设计**：外挂 OCR→markdown 会形成与模型大小无关的精度天花板，而金额、税号这类关键字段必须走「模型输出 + 规则/校验位复核」的双轨。

**必须前置说明**：本报告**没有任何一条关于「中文数电票/增值税发票在 1.5–2B 量级上的字段级精度」的直接实测数据**。所有对该场景的推断都是外推（见 §5）。

## 1. 已确认的发现（15 条确认 → 合成 10 条）

### 1.1 定位：小模型不是登顶者，但并非无竞争力

| 事实 | 数据 | 置信度 |
|---|---|---|
| 公开 IDP 榜单（29 模型 × 4 任务）**无任何开源小模型登顶** | Overall 第一 Nanonets OCR-3 85.9%、KIE 第一 Gemini-3-Flash 91.1% | 高 |
| 2B 量级可测但落后 | Qwen3.5-2B Overall **62.6**、0.8B **57.8**（榜首 85.9，差 ~23pt） | 高 |
| **但抽取轴上差距远小** | Qwen3.5-2B 的 KIE **78.5** vs 榜首 IDP Core 80.2 | 高 |

> ⚠️ 证据冲突提示：该榜单由 Nanonets 主办且其自家模型位列 Overall 第一，应作**初筛**用途，不能作采购依据。

### 1.2 瓶颈是「结构化输出合规性」，不是视觉能力（**对本项目最关键**）

VAREX（IBM Research，CVPRW 2026）：

- **≤4B 参数量的首要瓶颈是结构化输出合规性，而非抽取能力**；由 JSON Schema `$defs` 关键字触发的 **schema echo**（模型复述 schema 结构而非填入抽取值）会让受影响模型掉 **45–65 个百分点**；
- 因果机制：非合规率从「扁平 schema 的 2–3%」升到「含 `$defs` 时的 **68–69%**」；
- **内联 `$defs` 后**：Qwen3-VL 2B 从 27.4% → **91.8%**（+64pp）；InternVL3.5 1B 从 22.3% → **73.9%**（+52pp）；
- 该门槛**可被针对性训练消除**：NuExtract 2.0 2B（基座 Qwen2-VL 2B）从 **9.7% → 90.8% EM**，零 schema echo。

> 限定：语料是英文单页**数字原生**美国政府表单 + 合成值，无扫描件、无中文；且论文披露提示词不对称（NuExtract 用官方推荐格式，其余用通用零样本 JSON-schema 提示），+81pp 混杂了微调与提示工程两种因素。

**对本项目的直接含义**：我们调 Qwen-VL 做版式 PDF 抽取时，**prompt 里的 JSON schema 写法本身就是精度变量**——能用扁平 schema 就别用 `$ref/$defs` 嵌套。

### 1.3 管线设计 > 模型尺寸：外挂 OCR 是精度天花板

Fraunhofer IAIS/Lamarr（arXiv:2509.04469，IEEE BigData 2025）——**唯一以发票为主题的基准**：

| 输入方式 | Scanned Receipts 最好成绩 |
|---|---|
| Docling → markdown → LLM | **47.00%** |
| 原生图像直喂 LLM | **87.46%** |

- Clean Invoices 上，Docling 输入的 8 个模型全部被压在 **84.13–85.45%** 的窄带；原生输入则是 45.69–96.50%；
- 作者归因：「**初始 OCR 与 markdown 转换，而非 LLM 推理能力，成为结构化解析的首要限制因素**」。

> 限定：零样本云端模型（GPT-5 / Gemini 2.5 / Gemma 3 4B-12B）、英文合成发票与 SROIE 收据；「与模型大小无关」严格只在 Clean Invoices 上被证明。

### 1.4 关键标识符必须双轨复核（金额 / 税号）

同一论文：**即使前沿多模态模型，在 IBAN 这类无结构字母数字标识符上也系统性出错**，残余错误可追溯到 OCR 层字符混淆（数字 `0` 与字母 `O`/`U`）。Gemini 2.5 Pro 整体最高（clean invoices 96.50%），IBAN 仍是显著掉队的字段。

**对本项目的直接含义**：中国税号（18 位，含校验位）与金额（需价税合计 = 不含税 + 税额勾稽）必须走「模型输出 + 规则校验」双轨，不能直接信任模型原始输出——这正是 FRD 里「校验逻辑自洽、置信度 < 0.8 转人工」的技术依据，且**校验位算法是确定性的，比置信度阈值更可靠**。

### 1.5 识别阶段小模型够用（但证据来自不同域）

中文古籍页面级 OCR 上，**Qwen2.5-VL-7B 全面超过 72B**（Char F1 12.85 / CER 35.47 vs 10.06 / 58.83；GPT-4o 评分 6.37 vs 5.73）。作者归因：纯 OCR 只需字符识别与顺序输出，过度的理解与推理反而干扰输出。

> 限定：竖排繁体古籍、约 3000 页、绝对精度极低（全表最好的 Gemini2.5-Pro 只有 Char F1 18.12）；同表 Qwen2.5-VL-32B 在 P/R/F1 三列反超 7B——「越小越适合 OCR」**不是干净规律**。

### 1.6 成本模型：「大模型离线打伪标签 → 小模型蒸馏部署」已被完整实现

Qwen2-VL 2B/7B、Qwen2.5-VL-3B（及 Gemini/Claude API notebook）只用于**离线生成 OCR 标注文本**充当 ground truth；真正微调并部署推理的是 **256M 的 SmolVLM**。大模型成本只在标注期支付一次，而非每张发票运行时支付。

> 但只证明了「可训练」，未证明「可用于生产」：SROIE v2 347 张测试集上 CER 0.238，而该 CER 是**对着 Qwen2.5-VL-3B 生成的教师文本**算的（非人工 GT），仅约 76% 字符级一致度；教师自身 CER 0.279–0.313。来源为 9 star 单人演示仓库，单种子、单提示词、评测脚本有 bug。**低权重对待**。

### 1.7 部署侧：可算的账

**RK3588 + Qwen2.5-VL-3B（w8a8）**：

| 指标 | 实测 |
|---|---|
| 视觉编码固定开销 | 3.4s（三核并行） |
| LLM prefill | 2.3s（320 tokens / 138 tps） |
| decode | **8.2 tok/s** |
| 单张图片 + 结构化输出端到端 | **15–18s**（重排真实 A4 扫描件约 25–45s） |
| 峰值内存 | **6.19GB**（上下文 1024）→ 8GB 边缘板卡余量极小 |
| 驱动要求 | RKNPU2 内核驱动 ≥ 0.9.6 |

**单日 500 张 ≈ 5 小时**（500 × 36s）——**隔夜批处理可行，交互式不可接受**。

**内存账（易踩的坑）**：GGUF Q4_K_M 权重 1.93GB **之外**，做图像输入还需额外加载 **1.34GB 的 F16 视觉投影文件**（`mmproj`，卡片明确标注 required for image input）→ 真实权重预算约 **3.27GB**，不含 KV cache 与图像 token 激活。

### 1.8 量化代价

| 路线 | 结论 | 强度 |
|---|---|---|
| GGUF Q4_K_M vs FP16（Qwen2.5-VL-3B，TextVQA 200 题） | 72.33 vs 71.17，**-1.16pp**，McNemar p=0.727 → 「代价被约束在 ~1.2pp 以内」 | 中（n=200 单任务，严格 exact match 下为 -1.5pp） |
| RKLLM w8a8（RK3588） | 作者「已知问题」明确记录「**貌似存在不小的精度损失**」 | 中（定性，无量化；零发票字段级数据） |

**含义**：GPU/CPU 路线的 GGUF 量化风险可控；**边缘 NPU 路线的 w8a8 退化不能假定可忽略**。

### 1.9 吞吐已证明，但只限于吞吐

基于 RK3566（SoC 单价 < 12 美元）的 NANOMIND 在 Qwen2-VL-2B 4-bit 下达 **35.7 tok/s**，端到端比 Orange Pi 5 Ultra（RK3588）低 36.2%。

> 严格限定：依赖完整软硬协同栈（四通道 LPDDR4x 定制 PCB、专用 PMU、RKNN 转换的 SigLIP 视觉编码器、自定义 OpenCL W4A16 kernel），公开仓库尚不完整；评测集只有通用 VQA，**全文无 SROIE/CORD/receipt/invoice 字样**——对发票字段精度零证据。

## 2. 被对抗验证否掉的论断（10 条）

**这一节比 §1 更重要**——它划掉了容易被误引的乐观与悲观结论。

### 2.1 被否的「利好小模型」论断（4 条，**不得据此高估**）

| 论断 | 表决 | 为什么被否 |
|---|---|---|
| 1B 不可用、2B 才进入可用区间的能力门槛 | 0-3 | 门槛说在对抗验证中站不住 |
| 版式保留空间文本增益最大（+3~18pp），「小文本模型 + OCR 空间文本」可逼近更大 VLM 读图 | 1-2 | 该路线**未被证实** |
| Qwen2.5-VL-3B 权重可装进约 2GB 内存 | 0-3 | **漏算了 1.34GB 视觉投影**（见 §1.7） |
| CPU-only 跑 3B VLM 图像输入是「已记录的可工作配置」 | 0-3 | **CPU-only 无 GPU 路线的吞吐/可行性在当前证据下是空白，不是「已证明可行」** |

### 2.2 被否的「利空小模型」论断（3 条，**不得据此判死刑**）

| 论断 | 表决 | 说明 |
|---|---|---|
| gemma-3-4b-it 在 clean synthetic invoices 上崩到 45.69%（能力门槛） | 1-2 | 不能据此断言 4B 以下不可用 |
| 3B 教师模型自身 CER 0.313，形成 ~31% 上限 | 1-2 | 该 CER 数值未获确认 |
| 小 VLM 在难中文版式上 OCR 绝对精度远不够（InternVL2.5-2B Char F1 1.72 / CER 120.72） | 0-3 | 这些极端数字未获确认 |

### 2.3 其他（3 条）

- 「IDP Core 的 KIE 任务是发票/收据导向」——0-3 被否，**削弱了该榜单对本场景的代理性**；
- 「小 VLM 在中文文档上的退化是任务特定的」——0-3 被否；
- 「RKNN 无法承载 LLM 解码器」——0-3 被否（RK3588 实际可跑 w8a8 解码，与 §1.7 一致）。

## 3. 对 InvoiceEase 的落地建议

### 3.1 推荐架构（哪一环用小模型、哪一环必须大模型或人）

```
数电票 XML / 内嵌 XBRL 的 OFD ──▶ 直解，不过模型          [规则，最省最准]
        │
纯版式 PDF / 扫描件 ──▶ ① 识别（OCR 或小 VLM）
        │                ② 首轮字段抽取（小模型 + 约束解码）
        │                ③ 确定性门控：税号校验位 + 价税合计勾稽 + 大小写金额一致
        │                     ├─ 全通过 → 高置信，直接进验真查重
        │                     └─ 任一失败/低置信 → ④
        └──▶ ④ 7B+ / 云端大模型兜底 ──▶ ⑤ 仍存疑 → 人工复核
模糊件（照片/低质扫描）──▶ 多模态大模型直接读图（**不要先转 markdown**）
```

三条硬结论支撑这个形状：

1. **能不过模型就不过模型**——XML/OFD 直解已经是 FRD 的第一级路由，本调研进一步确认这是正确的优先级；
2. **不要外挂 OCR→markdown 再喂 LLM**（§1.3：47% vs 87% 的鸿沟）；如果走 OCR 路线，应喂**版式/坐标信息**而非线性 markdown；
3. **关键字段的双轨校验比置信度阈值更可靠**（§1.4）——税号校验位、价税合计勾稽是确定性算法，不依赖模型自评。

### 3.2 若要做离线/私有化部署（企业版），当前证据支持的判断

| 场景 | 判断 |
|---|---|
| **CPU-only 服务器跑 3B VLM 读图** | ⚠️ **证据空白**，不可默认可行（§2.1）；必须自测。内存预算按 ≥3.3GB 权重 + KV cache 估 |
| **入门 GPU（T4 / 4090 / 8–24GB）** | ⚠️ 同样**零实测证据**（研究明确列为开放问题）；T4 显存够跑 3B fp16，但吞吐需自测 |
| **RK3588 类边缘 NPU** | ✅ 可行但**只适合隔夜批处理**（500 张 ≈ 5 小时）；**交互式不可接受**；w8a8 精度退化无量化数据，不能用于金额/税号的关键判定 |

### 3.3 如果要走「小模型自研」路线

已被验证的路径是 **蒸馏**（§1.6）：用现有云端大模型（DeepSeek / Qwen-VL API）离线打伪标签，微调小模型部署。**但教师的能力上限会被继承**——所以：

- 打标签阶段就要跑「税号校验位 + 价税合计勾稽」过滤，**只把通过校验的样本喂进训练集**；
- 蒸馏的 CER 必须对着**人工标注的小样本**校准，不能对着教师输出自评（§1.6 的教训）。

## 4. 证据空白与必须先做的实验

调研明确列出的开放问题，**任何选型定档前必须先补**：

1. **中文数电票/增值税发票在 1.5–2B 上的真实字段级精度与幻觉率**——公开基准（SROIE/CORD/FUNSD/DocVQA/VAREX）全部是英文或英文收据，**必须自建评测集**（含版式 PDF 扫描件、数电票 XML/OFD、长尾版式）。
2. **纯 CPU（无 GPU）跑 3B 级 VLM 图像输入的实际吞吐与单张延迟**——现有论断被否，完全空白。
3. **国产 NPU 上 w8a8 对金额/税号等关键字段的端到端退化幅度**——目前只有定性记录。
4. **用 Qwen2.5-VL-3B/7B 当教师给中文发票打伪标签，其自身在税号/金额上的错误率是否低于人工复核门槛**（如置信度 0.8）。
5. **约束解码 / schema 内联 / few-shot 能否替代微调**达到同等结构化输出合规率——VAREX 只验证了「微调可绕过门槛」，而 `$defs` 内联在 `$ref` 嵌套结构必需时不可用。

## 5. 本报告的不确定性（必读）

1. **证据域严重不匹配（最大风险）**：唯一以发票为主题的基准用英文合成发票 + 英文/马来文收据，模型是云端大模型；「小模型可承担识别」的证据来自中文古籍与英文收据；「2B 抽取可用」的证据来自英文单页数字原生美国表单。**所有对中文发票的推断都是外推。**
2. **榜单利益冲突**：idp-leaderboard.org 由 Nanonets 主办、其自家模型位列第一。
3. **四条用户可能期待的乐观结论已被否**（§2.1），选型时不能默认 CPU-only 可行。
4. **低质量来源**：SmolVLM 蒸馏证据来自 9 star 单人仓库（伪标签自评、脚本有 bug）；TextVQA 量化对比来自 14 star 自发布仓库、n=200 单任务——均已降权处理。
5. **时间敏感性**：榜单为 2026-09 快照（含 GPT-5.4 / Gemini-3-Pro），**约半年保质期**；RKLLM/RK3588 数据约为 2025 年中，社区提速路径已转向换模型（Qwen3-VL-2B 约 15 tok/s）而非同模型优化。
6. **引文落点**：Lamarr 出版页只载 arXiv 摘要，承载引文的是论文正文第 IV 节。
