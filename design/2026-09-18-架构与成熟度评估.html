一、一句话结论

比 09-16 又进了一档：从「单租户内网 MVP」到「带运维骨架的单租户内网 MVP+」。 运维兜底从零到基本可用是本阶段最大增量（日志轮转 / 7 条告警规则 / 备份恢复 / 启动自检 / 运维页）； 回单从「记录」进化为「业务对象」（交易性质分类接入月报、配对、催票，删除带快照审计）。 但三大商用硬差距原封未动——验真仍是模拟、安全基线仍是开发默认、生产部署物仍不存在。

离「可收费」的那一步依然完整，只是每一步的入口比两周前更清楚了。

四、仍然原封的硬差距（今日逐条复核，均有 file:line）

B1 验真仍是模拟

verify/provider.py:19-22 无真实国税 API 代码路径；披露机制健在（verify_is_mock、前端橙色 tag、月报声明）。

六、上线路径修订（M1 / M2 / M3 增量版）

M1 · 安全收口（本机即可做，1 周量级）——比 09-16 更省：自检框架已在位，大部分是「补默认值与裁决」

  1. 生产 profile 置 startup_checks_strict=true，弱 jwt_secret / admin123 即 fail-fast（机制已在 checks.py，只差配置与文档裁决）
  2. CORS / TrustedHost 中间件；登录限流（重新评估已裁决项）；workbuddy_inbox_dir 生产必填校验；legacy MCP token 默认关闭（部署留空即禁用的开关已有，改默认值）
  3. dayjs 显式声明；verify_is_mock 判定去字符串耦合（改用结构化标志）；离线模式 LLM 端点启动校验（R6）

M2 · 生产化对齐（需有 Docker 的环境）

新增一条：backup.py PG 支持（切 PG 前 must）；其余同前：应用 Dockerfile + compose + nginx/TLS、PG 迁移实测（naive-UTC 雷）、redis/arq 实测、S3 测试、CI。

M3 · 合规与验收（外部依赖驱动）
