# 回单收款/付款信息增强方案

日期：2026-09-12 ｜ 状态：**P0/P1/P2 已实施**（迁移 c8d1e4f6a2b3；真实 PDF 验证：手续费/利息 → 对方户名留空 + no_counterparty + 待核对；18 条方向全部正确）

## 问题现象

回单列表 18 条中有 2 条对方户名异常（#6 手续费 899.00、#17 活期利息 0.17）：

```
西安启智合创科技有限公司 账号： 61050174004100000779
```

即「本司户名 + 账号残留」，对下游无意义，且会污染配对与凭证导出。

## 根因（代码级）

### R1 这类回单**根本没有对方户名字段**

建行手续费/利息回单是银行内部交易，原文只有本司账户行：

```
户名： 西安启智合创科技有限公司 账号： 61050174004100000779
项目名称 工本费/转账汇款手续费/手续费 金额
合计金额 （大写）人民币捌佰玖拾玖元整 ￥899.00
```

税票回单有「收款国库/征收机关」（规则关键词已覆盖，取值正确 14 条）；
转账回单竖排文字规则不匹配 → 交 LLM，LLM 取「付款人全称 贾琨」为对方（5 条正确）。
唯独这两类版式：唯一的 `户名` 行是**账户持有人=本司**，规则当成对方户名取走。

### R2 取值未清洗：捕获串跨字段

`_PARTY_RE` 捕获 `[^\n]+` 整行，把行内后续字段（`账号： 6105…`）一并带走。
同类风险存在于任何「户名/账号同行」的版式。

### R3 质量校验缺失：错值静默入库

- `_llm_fill_fields` 仅在**金额/户名缺失**时触发；本例两字段“有值”（只是错值）→ LLM 无机会纠正
- 解析产出后无任何校验（是否为空、是否本司、是否含标签残留），无 `needs_review` 标记
- 前端/MCP 只能靠人眼发现

### R4 本司识别手段缺失（且现有字典对不上）

`company_info` 里 kind=self 是「澜铮鸿欣（上海）数字科技」（91310101MAELA36R35），
而回单账户户名是「西安启智合创科技有限公司」——**名称对不上，无法用现有字典判定本司**。
可靠的判定信号是**本司银行账号**（`61050174004100000779`），当前无任何配置位。

### R5 配对受污染

`suggest_pair` 用「金额相等 + 户名规范化后互相包含」；本司名+账号串既可能匹配不上
（漏配对），也可能与本司自己开的发票误配。

## 增强方案（分层，建议按 P0→P2 推进）

### P0 取值清洗 + 质量标记（低成本，立即收益）

1. **捕获清洗**：`parse_receipt_text` 产出的户名做后处理——剥离行内后续字段标签
   （`账号|开户行|开户银行|户名|收款人|付款人|税号` 等）及其后内容、去引号/空白。
   影响：`户名： 西安启智… 账号： 6105…` → `西安启智合创科技有限公司`。
2. **质量标记**：`bank_receipts` 增加 `needs_review`（bool）+ `quality_issues`（JSON 数组），
   解析后统一校验并写入：
   - 户名为空
   - 户名含账号/标签残留（清洗后仍命中）
   - 户名命中「本司账户户名」（见 P1 配置；未配置时跳过）
   - 金额缺失
3. **前端/MCP 呈现**：列表对 `needs_review` 行高亮 + 可筛选「待核对」；
   `receipt_list` 输出 `needs_review/quality_issues`。

### P1 本司银行账户配置 + 语义兜底

4. **本司账户登记**：`company_info`（kind=self）增加银行账户字段，或新增
   `bank_accounts` 配置（账户号 + 户名，支持多账户）；解析时用**账号**判定
   「本司账户行」——名称不可靠，账号可靠。
5. **无对方户名版式的语义处理**（手续费/利息等银行内部交易）：
   - 判定为本司账户行 → 对方户名**留空**（不臆造），`abstract` 已有语义（手续费/活期利息）
   - 标记 `quality_issues=["no_counterparty"]` + `needs_review`（金额+摘要已可入账，
     对方建议统一记「银行」由财务确认，或提供映射规则）
   - 若 LLM 可用，扩展触发条件：**质量校验未过**（而非仅字段缺失）也允许 LLM 复核一次，
     但**禁止**把本司名当对方（prompt 明确 + 结果校验）

### P2 收/付方向与配对健壮性（会计口径完善）

6. **收付方向**：增加 `direction`（收/付/内部）字段——由版式语义推断
   （贷方回单/收款人回单=收；缴款书/手续费=付；利息=收），LLM 兜底；凭证草稿
   的借贷方向随之准确（当前 CSV 恒「借费用/贷银行」）。
7. **配对排除本司**：`suggest_pair` 候选排除户名命中本司账户的记录方向；
   本司命中时不做名称包含匹配，避免错配。

## 验收（P0+P1）

- 真实建行 PDF：#6/#17 户名清洗为裸名称或被标记 `no_counterparty` + `needs_review`；
  其余 16 条不受影响且无新增标记
- 前端「待核对」筛选可用；`receipt_list` 带出标记
- 全量测试绿；新增：清洗用例（账号残留/引号/多标签）、本司账号判定用例、
  手续费/利息版式用例
