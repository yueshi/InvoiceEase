## 一、数字员工实现机制（产品核心）

### 1.1 任务引擎（心脏）——主动任务循环

```
班表（scheduler 任务目录）        任务循环五步
──────────────────────          ──────────────────────
每日 09:00   收取邮件            感知（查库：有什么待办）
每票落库后   复核预判            → 决策（规则快判断 + LLM 慢判断）
每周一 09:00 催交票提醒         → 行动（调 MCP 工具）
每月 1 日   生成健康报告        → 汇报（自然语言结果 + 推送）
                                → 留痕（审计，全部可追溯）
```

工程：现有 `scheduler.py`（仅邮箱轮询）扩展为任务目录（task catalog），每任务 = 一项岗位职责。任务注册、启停、频率可配。

### 1.2 工具边界（双手）——MCP 工具即能力边界

- 现有 13 工具 = 数字员工已有技能；每工具带审计 = 技能留痕
- P1 新增 3 工具：`invoice_ai_review`（复核预判）、`invoice_classify`（费用归类）、`invoice_report`（成本报表）
- 原则：所有新能力先落 REST/MCP 原子工具，再由 SKILL 层编排

### 1.3 分层决策（大脑）——快思考/慢思考

```
快思考（确定性规则，毫秒级、零成本、永不幻觉）：
  查重命中 → 拦截；金额矛盾 → 拦截；字段完整校验全过 → 通过
慢思考（LLM，有理解力、可解释）：
  边缘票预判、费用归类、异常解释、汇报话术
工作手册（SKILL 提示词 = SOP）：
  工具调用顺序、判断标准、升级规则、汇报模板
```

工程原则：**每个决策必须带「理由」**——规则命中写规则名，LLM 判断写 reason 文本；可解释性是信任前提。

### 1.4 渐进自主与信任（岗位纪律）

```
观察期（上线即启）  → 只建议不执行，财务确认
授权期（1-2 周后）  → confidence ≥ 0.95 自动执行（仅「通过」方向；拦截永不自动）
全权期（稳定后）    → 阈值下探 0.90，范围扩至归类/提醒
```

- 每个自动动作审计留痕（含决策理由）；回滚路径已备（unblock / 字段重编辑）
- **信任仪表盘**：数字员工绩效页——本周自动处理 N 张、人工改判 M 张、改判原因分布。用数据证明可靠

### 1.5 三个 Wow Moment（体验锚点）

| 时刻 | 场景 | 感受 |
|------|------|------|
| 周一早上 | 老板打开 WorkBuddy，数字员工**主动汇报**：「上周收 12 张票，11 张已处理，1 张待确认（理由：抬头存疑）；本月差旅 3.2 万，环比 +18%…」 | 「它真的在替我看着」 |
| 异常票 3 秒 | 问题票 → 解析+预判+拦截理由一气呵成 → 财务点「同意」 | 「复核从分钟到秒」 |
| 员工一句话 | 「票交了吗？」「交了，数字员工说抬头没问题，已挂到 6 月差旅。」 | 「全公司都在用」 |

## 六、风险与验收

| 风险 | 控制 |
|------|------|
| LLM 幻觉 | 规则优先三层架构 + 人工确认期 + 审计全留痕 |
| 自动误判 | 阈值渐进（拦截永不自动）+ unblock 回滚 + 信任仪表盘 |
| WorkBuddy 主动推送能力未知 | P1 第一天验证；不支持则降级 Web 通知 + 企微机器人 |
| 红冲规则不严谨 | 开发前财务确认规则（P2 动工前） |
| 前端 UX 投入低估 | 交互先「够用」，后续打磨 |

**验收指标**：复核耗时 3 分钟→10 秒；月结耗时半天→10 分钟；授权期自动处理率 ≥80%；信任仪表盘改判率 <5%。
