# 电子发票报销功能调研 + 发票易报销功能设计

日期：2026-09-13 ｜ 状态：**设计已确认（4 项开放问题已定，见 §五）；未实施**

## 一、调研：电子发票报销系统的功能清单（外部基线）

政策依据：
- **财会〔2025〕9 号**《关于推广应用电子凭证会计数据标准的通知》（财政部等九部门，2025-05）：
  会计软件须在《会计信息化工作规范》（财会〔2024〕11 号）施行起 **3 年内升级**适配；
  对符合标准的电子凭证须支持**无需转换**地完成「接收（验签/验真/解析）→ 报销 → 入账 → 归档」全流程；
  明确支持的凭证种类：XML 数电票、内嵌 XBRL 的 OFD 数电票、内嵌 XML 的 PDF 财政电子票据、
  银行电子回单/对账单等
- **财会〔2020〕6 号**：电子会计凭证报销入账归档规范

主流系统功能清单（归纳自用友畅捷通、泛微业票通、每刻、汇联易、铁山等公开资料）：

| 环节 | 典型功能 |
|------|---------|
| 归集采集 | 税务数字账户一键取票、邮件/微信卡包接入、扫码上传、OCR 识票、个人票夹/企业发票池 |
| 查验校验 | 验真、**查重**（跨主体跨时段）、验签、抬头/黑名单/有效期校验、价税分离 |
| 报销 | 移动填单、从票夹选票一键发起、多张票据批量、报销单-发票-申请单关联、**多级审批流**、进度可查 |
| 费控 | 预算冻结/占用、费用标准（时间/城市/职级）、柔性/刚性控制、信用抽审 |
| 支付 | 银企直联、批量支付、收款认领 |
| 入账 | 自动凭证生成、科目匹配、ERP 回写、进项认证抵扣 |
| 归档 | 电子档案自动归档、**按凭证号关联成册**（凭证+报销单+发票+回单）、**四性检测**、全生命周期管理 |
| 调阅审计 | 穿透联查、审计抽凭、权限与调阅日志 |

实践数据：中石化电子凭证累计 2400 万张、报销电子化率 94%、银行回单匹配率 100%；
湘潭大学无纸化报销最快 30 分钟全流程完成。

**关键洞察**：主流产品的**重复报销控制**都不是靠"标记"，而是靠**发票池查重 + 流程前移**
（每刻在填单/审核阶段查，汇联易在发票池做一次、报销与对公复用）。发票易已有全库查重，
天然契合——只需补"报销状态"维度。

## 二、发票易的定位与差距

### 定位（不做全面费控）

发票易的差异化是：**发票自动化 + Agent 接入 + 合规归档**（邮箱自动归集、MCP 对话式操作、
XML 原件与审计留痕）。因此报销功能做**轻量闭环**，不与每刻/汇联易在预算费控、商旅预订、
银企直连上正面竞争。

**明确不做（YAGNI）**：预算与费用标准、商旅/机酒预订、银企直连支付、信用抽审、进项抵扣认证。

### 差距分析（现有能力 vs 报销闭环）

| 能力 | 现状 | 缺口 |
|------|------|------|
| 发票归集 | ✅ 邮箱轮询 + MCP 导入 | — |
| 验真 / 查重 | ✅ 全库唯一键 + 验真 provider | — |
| 原件归档 | ✅ XML 原件单独存档 | — |
| 审计留痕 | ✅ audit_logs（含 outcome 结果类别） | — |
| 银行回单 | ✅ 多银行解析 + 配对 | — |
| **报销单** | ❌ | 需新建 |
| **发票报销状态** | ❌（只有业务状态机） | 需新增维度 |
| **一票一报约束** | ❌ | 需 DB 级唯一 |
| **审批** | ⚠️ 仅有发票复核（单人） | 需报销单审批 |
| **入账/凭证** | ⚠️ CSV/Excel 导出 | 报销单维度导出 |

## 三、功能设计

### 3.1 数据模型

```
expense_claims 报销单
  id / tenant_id / claim_no(单号 FY-YYYYMM-####) / applicant_id(申请人)
  title(事由) / total_amount / status / current_approver_id
  submitted_at / approved_at / rejected_reason / remark
  created_at / updated_at

expense_items 报销明细（报销单 ↔ 发票/回单）
  id / claim_id / invoice_id / receipt_id(回单，无票支出用) / amount
  expense_type(差旅/办公/招待/采购/其他) / note
  唯一约束：(invoice_id) 在"有效报销单"内唯一 → **一票一报**的 DB 级保证
  （发票可与多个"已驳回/已撤回"单据关联过，故唯一索引建在有效状态的物化字段上）

invoices 增加 reimbursement_status（none/pending/claimed）
  pending=已被草稿/审批中的报销单占用；claimed=已通过并归档
```

### 3.2 状态机

```
draft ──submit──> pending_approval ──approve──> approved ──archive──> archived
  ↑                    │                                              │
  └──reject/withdraw───┘                                     （发票 reimbursement_status=claimed）
```

- **draft**：可选票、可改；占用发票（防止他人同时在填）
- **pending_approval**：锁定不可改，等待审批（**单级**：财务角色任一人可通过/驳回）
- **approved**：发票标记 `claimed`；金额进入"已报销"口径
- **archived**：报销单 + 明细 + 发票原件 + 审计形成归档包（P1）

### 3.3 关键校验（合规）

1. **一票一报**：提交时校验 `invoice.reimbursement_status == none`，DB 唯一约束兜底
2. **必须先验真**：`verify_status != passed` 的发票不允许提交（政策要求 100% 验真）
3. **抬头校验**：购买方非本司的发票警示（已有 company_dict 能力可复用）
4. **金额一致 + 整票报销**：明细合计 = 报销单总额；**每条发票明细金额必须等于该发票全额**
   （P0 不支持拆额；P1 放开为"累计不超票面"）
5. **状态联动**：发票被 `blocked`（重复拦截）时不允许加入报销单
6. **无票支出**：允许用银行回单作为明细（复用现有回单配对；凭证要求见 §3.3b）
7. **可选票范围**（员工发起时）：`user_id == 本人` 的发票 ∪ **公共池未被占用**的发票
   （邮箱归集的票无归属人，属公共池；占用与否由一票一报约束判定）

### 3.3b 无票支出的凭证要求（合规基线）

依据《企业所得税税前扣除凭证管理办法》（**国家税务总局公告 2018 年第 28 号**第九条）
与《增值税暂行条例》起征点规定（财税〔2016〕36 号）：

| 对方主体 | 允许的扣除凭证 |
|---------|--------------|
| 已办理税务登记的纳税人 | **必须发票**（含税务机关代开） |
| 依法无需登记的单位 | 代开发票 **或** 收款凭证 + 内部凭证 |
| 从事**小额零星**经营的个人 | 代开发票 **或** **收款凭证 + 内部凭证** |
| 不属于增值税应税项目 | 单位为对方：其他外部凭证；个人为对方：**内部凭证** |

**收款凭证法定必备要素（缺一不可）**：收款单位名称 / **个人姓名及身份证号** /
支出项目 / 收款金额。

**"小额零星"判定** = 不超过增值税起征点：按次 **300–500 元**（各省幅度内自定）、
按月 5000–20000 元 → 系统**阈值可配置**（默认 500），不硬编码。

#### 凭证类型枚举与校验（明细行 `voucher_type`）

| voucher_type | 适用场景 | 必填要素 | 税前扣除 |
|--------------|---------|---------|---------|
| `bank_receipt` | 银行手续费/利息/转账 | 回单（**已有自动解析**） | ✅ 直接扣除 |
| `tax_receipt` | 社保/公积金/税费缴纳 | 缴款书回单 + 税票号码（**已有**） | ✅ 直接扣除 |
| `receipt_voucher` | 小额零星采购（买菜/补胎/搬运） | **收款人姓名 + 身份证号** + 项目 + 金额 | ✅ 需要素齐全 |
| `internal` | 工资薪金/差旅补助 | 内部单据附件 + 审批记录 | ✅ 属非应税项目 |
| `contract` | 违约金/赔偿 | 合同附件 + **非现金付款凭证** | ⚠️ 仅特殊情形（对方注销/非正常户等） |
| `overseas` | 境外支出 | 境外票据 + 付款凭证 | ✅ 无需境内发票 |

#### 系统自动提示（财务风险控制）

1. 按次金额超**可配置阈值** → 提示"已超小额零星标准，需取得发票"
2. `receipt_voucher` 要素不全 → 标记**不可税前扣除**，汇算清缴前可一键筛出
3. 应取得未取得发票的：提示**汇算清缴结束前**可要求对方补开/换开；
   无法补开的按 28 号公告提供「无法补开证明 + 合同协议 + 非现金付款凭证」，
   追补期限 **5 年**

### 3.4 页面

| 角色 | 页面 | 功能 |
|------|------|------|
| 员工 | 我的报销（新建 `/expenses`） | 选发票（**本人上传/导入的 + 公共池未占用**，仅显示未报销且验真通过）→ 填事由/费用类型（五类）/备注 → 提交 → 进度查看 → 撤回 |
| 员工 | 发票列表（已有） | 行内新增「加入报销单」入口；显示"已报销/报销中"标记 |
| 财务 | 报销审批（`/expenses` 管理视图） | 待审批列表、批量通过/驳回、驳回理由、查看明细与发票原件 |
| 财务 | 报销单导出 | 凭证草稿（金蝶/用友列，复用 reports 模式）+ 归档包（P1） |

### 3.5 MCP 工具（Agent 侧，与 WorkBuddy 对话报销）

| 工具 | 用途 |
|------|------|
| `expense_create` | 创建报销单（标题/费用类型），返回单号 |
| `expense_add_invoices` | 按发票号/ID 加入明细（自动校验一票一报、验真） |
| `expense_submit` | 提交审批（返回状态） |
| `expense_list` | 我的报销单列表（状态/金额/张数） |
| `expense_approve` | 财务审批（approve/reject + 理由） |
| `expense_report` | 报销统计（月度/部门/费用类型） |

**对话示例（WorkBuddy）**：
> 用户："把上个月的打车票报销了" → Agent 调 `invoice_list`（筛选本人 6 月发票）→
> 确认清单 → `expense_create` + `expense_add_invoices` → `expense_submit` →
> 回复"报销单 FY-202606-0007 已提交，共 5 张 1,234.00 元，等待财务审批"

### 3.6 与既有能力的衔接

- 发票状态机不变，**新增正交维度** `reimbursement_status`（避免污染现有 12 状态）
- 审计：报销单的每个动作写 audit_logs（action=EXPENSE_*，带 outcome 结果类别）
- 回单：无票支出明细走 BankReceipt（已有配对/未配对视图）
- 报表：月度成本报表增加"已报销/未报销"口径

## 四、分期实施

| 期 | 内容 | 价值 |
|----|------|------|
| **P0** | 报销单模型 + 一票一报（DB 唯一）+ 状态机 + 员工新建/提交/撤回 + 财务审批 + 发票列表标记 + MCP 三工具（create/add/submit）+ **无票支出（回单/缴款书优先）与凭证要素校验（§3.3b）** | 闭环可用，防重复报销落地 |
| **P1** | 多级/条件审批（金额阈值）、批量审批、凭证草稿导出（报销单维度）、部分报销、归档包（四性检测最小实现） | 贴近财务实操 |
| **P2** | 费用标准与预算（柔性/刚性）、商旅集成、发票池自动匹配建议（按行程/时间聚类） | 向费控延伸 |

## 五、决策记录（2026-09-13 已确认）

| # | 问题 | 决策 | 影响 |
|---|------|------|------|
| 1 | 审批模型 | **P0 单级财务审批**（财务角色任一人可通过/驳回，同现有发票复核模式） | 条件流后续同模型扩展，不回退数据结构 |
| 2 | 部分报销 | **P0 整票报销**（明细金额 = 发票全额） | 一票一报可用 DB 唯一约束直接保证；P1 放开拆额不改表 |
| 3 | 费用类型 | **固定五类 + 明细备注自由填写**（差旅/办公/招待/采购/其他 + note） | 与发票归类、月度报表口径一致；无需类型管理 |
| 4 | 员工可选范围 | **本人 uploaded 的 + 公共池未占用的**（邮箱归集票无归属人） | 需在选票接口按 `user_id=本人 OR user_id IS NULL` + 未占用过滤 |
