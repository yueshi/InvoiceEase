# 常用企业银行账号 + 多银行回单高质量支持

日期：2026-09-13 ｜ 状态：待确认

## 一、常用企业银行账号（管理模块）

### 现状问题

本司账号目前寄存在 `company_infos.bank_account`（kind=self 的单个字段）：
- 一家公司多账户（基本户/一般户/外币户）无法表达
- 与「公司/税号」语义混在一起，无法单独开户行、别名、启停
- 回单解析的「本司账户行」判定只认这一个账号

### 设计

**新表 `bank_accounts`**

| 列 | 说明 |
|----|------|
| id / tenant_id | 主键与租户 |
| account_no | 账号（数字，唯一）——本司账户行判定的**唯一可靠依据** |
| account_name | 户名（回单上打印的账户名称，可能与公司名不同，如简称） |
| bank_name | 开户行（建行西安蓝湖树小区支行…） |
| remark / is_default / enabled | 备注、默认标记、启停（停用不参与判定） |

**接口与界面**
- REST：`GET/POST/PUT/DELETE /api/v1/bank-accounts`（admin 写、财务读；与 company_infos 权限一致）
- MCP：`bank_account_list / bank_account_save / bank_account_delete`（WorkBuddy 可维护）
- 前端：系统配置新增「常用银行账号」tab（表格 + 新建/编辑弹窗）

**解析接线**
- `self_account_set(db)` 改为读 `bank_accounts`（enabled）∪ 兼容读取 `company_infos.bank_account`
- `self_name_set(db)` 额外纳入 `bank_accounts.account_name`（户名可能是简称）
- 迁移：把现有 `company_infos.bank_account` 非空值迁入新表；旧列保留只读兼容

**为什么账号比名称可靠**（已有实证）：公司字典里的本司名与回单账户户名可以不一致（实测「澜铮鸿欣」vs「西安启智合创科技」），而账号是稳定的。

## 二、多银行回单高质量支持（方案）

### 现状与瓶颈

当前解析对建行已高度适配（分块标记、标签关键词、方向规则），但**都硬编码**：
- 分块只认「此回单以客户真实交易为依据」
- 户名标签只认「对方户名/收款国库/征收机关…」
- 换一家银行（工行「回单编号」、招商「电子回单」、农行…）→ 规则全失效 → 全靠 LLM（慢、贵、不稳定）

### 总体策略：模板库驱动 + 分层降级 + 语料回归

```
① 银行识别 → ② 模板驱动规则解析 → ③ 版面感知补强 → ④ LLM 块级兜底 → ⑤ 质量门/人工核对 → ⑥ 修正沉淀回模板
```

### P0 骨架（把「改代码接一家银行」变成「加配置 + 加语料」）

1. **银行识别**：内置各行检测关键词（"中国建设银行"/"中国工商银行"/"招商银行"/"中国农业银行"…），命中即记录 `receipt.bank_code`；列表可按银行筛选
2. **模板库**（内置 YAML 默认 + DB 覆盖）：
   - `detect_keywords`：识别该行
   - `block_head_markers / block_end_markers`：分块标记（**多值**，兼容"一页一张"与"一页多张"）
   - `field_labels`：字段标签别名表（date/party/amount/abstract/direction 各自的标签数组）
   - 建行为首份内置模板（把现有硬编码迁移过去），其余银行留空走兜底
3. **解析器模板化**：规则层读模板而非硬编码；无模板银行 → LLM 块级兜底（现有能力）+ needs_review 标记
4. **回归语料**：`test/fixtures/receipts/<bank>/*.txt`（脱敏文本 + 期望字段表），表格驱动测试——接入新行 = 补语料，防回归
5. 前端：列表显示银行标识；详情页显示解析路径（模板/LLM）

### P1 质量提升（复杂版式）

6. **版面感知解析**：用已具备的 PDFium 坐标做行聚类、左右分栏、标签-值配对——解决「标签与值分离」「竖排逐字」（建行手续费/转账已踩过）
7. **字段级校验**：账号格式、日期合理性、金额与明细行合计一致、同文件多张交叉校验；不达标 → needs_review（已有机制）
8. **LLM 结构化输出**：JSON schema 强约束 + 回读校验，降低幻觉字段

### P2 学习闭环（越用越准）

9. **人工修正沉淀**：详情页修正字段 → 记录差异；同一版式重复出现时提示「沉淀为模板标签」（半自动）
10. 模板管理 UI（查看/编辑/启用银行模板）

### 验收（P0）

- 建行回单：解析结果与现状**完全一致**（模板化不回归）
- 新银行（无模板）：走 LLM 兜底 + needs_review，不产生空壳
- 假造第二家银行样本（如工行版式）→ 新增一份模板 + 语料即可解析，无需改代码
- 银行标识、解析路径在前端可见、可筛选
