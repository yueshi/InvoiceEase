A4 真机冒烟（1 天；2026-08-18 验收清单先冒烟、全项留 PoC 现场验证）

  • 真实邮箱 IMAP 收票全链路（真实数电票 XML/PDF 各 ≥1 张）
  • 企微 webhook 真实推送（告警 + 月报通道各触发一次）
  • WorkBuddy 真机挂载：个人令牌签发 → Agent 真实调用 invoice_list / invoice_ingest
  • 员工真实上传 + 报销全流程走通（含无票支出、回单挂载两条新路径）

B · 流程侧（约客户之前谈定）

  • 客户画像核验：数电票 XML/PDF 原件为主；1-2 名专职财务；接受陪跑模式。大量拍照/扫描件的客户不接（OCR 未部署）
  • 约法三章（书面，进试用协议附件）：
    • 验真模拟声明 + 财务人工国税平台查验 SOP（明确「系统验真为模拟、需人工查验兜底」）
    • 图片件拒收口径（仅收原件，财会〔2025〕9 号）
    • PoC 期间 bug 由我方人肉响应（明确响应方式与时段）
    • 数据退出路径：Excel 台账导出 + originals 原件打包，PoC 结束可带走
  • 部署形态定死：客户内网 Linux 服务器 + systemd 手工部署（绕开无 Dockerfile 与 macOS 日志截断 K1）；数据不出客户内网
  • 前置问清：客户是否要求「自动验真」才用——是要，就不签（等 B1 国税资质）

C · PoC 期间风险认知（不解决，但要有预案）

#风险预案
1无部署物，修 bug 全靠人肉上客户机器PoC 并发 = 1-2 家，不贪；修复窗口提前约定
2验真 mock 话术风险见 B「前置问清」；话术备好「全行业同等待资质」
3单进程 + SQLite，调度器与 API 同进程，重启丢任务部署文档写清升级窗口操作（先停 API 再起）
4PoC 结束数据绑定猜疑退出路径已写入协议（B）

D · PoC 复盘指标（两周后回看）

  • 财务节省时间：单张票 3-5 分钟 → 30 秒内（含人工查验动作的口径要分开统计）
  • 人工复核率 / 解析准确率（分票型统计：XML / XBRL PDF / 版式 PDF）
  • 改判埋点数据积累（决定 auto_review_threshold 是否开启）
  • MCP/数字员工路径真实使用频次（决定盒子里 MCP 是否主界面）
  • 客户撞到的 Top 问题清单（回填 roadmap）

E · 明确不在 PoC 前做（边界）

部署物/TLS/PG/Redis（M2） 验真真实化（M3，等国税资质） OCR 部署 盒子 PoC（种子启动后） 多租户 分布式限流
