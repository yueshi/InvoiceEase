# Agent 跳转 Web 后台：深链 + 免登票据设计

- **日期**：2026-10-03
- **状态**：已实施（2026-10-03）；实施偏差见文末「实施记录」
- **范围**：WorkBuddy 等 MCP Agent（含定时推送）把用户一键带到 Web 后台「正确的那一屏」；不新增页面，只让现有页面可被深链

---

## 1. 背景与目标

现状三个缺口（已核对代码）：

| 缺口 | 位置 |
|---|---|
| MCP 工具出参不含任何 URL | `backend/src/invoicing/mcp/tools.py`（仅 `file_url` 存储 key） |
| 后端无 Web 对外地址配置 | `config.py` 只有 `cors_origins` / `mcp_issuer_url` |
| 前端不可深链 | 路由无 query 支持（`InvoiceListView.vue` 不读 `useRoute`），跨端跳转必落登录页重登 |

**目标**：Agent 对话/推送里给出的每条结论，都能附一个链接，点击后：
1. 落到**已筛选好的目标页**（如 `/invoices?status=pending_review`，而非首页）；
2. **免登录**（未登录浏览器也一键进入会话）。

**非目标**：MCP Apps 内嵌渲染（`ui://`，依赖宿主支持，另行评估）；401 拦截器不带 redirect 的既有行为（不在本次范围）。

## 2. 方案总览

### 2.1 链接形态

```
{web_base_url}/invoices?ticket=<一次性JWT>&status=pending_review
```

一条链接同时携带**目标路径 + 业务筛选参数 + 一次性票据**。票据不是独立跳转页，而是路由守卫里"顺手兑换"的参数。

### 2.2 数据流

```
WorkBuddy 对话 / 微信推送
   │  用户点链接
   ▼
浏览器打开 /invoices?ticket=X&status=pending_review
   │
   ▼ 前端路由守卫（router/index.ts beforeEach）
   ├─ 已有会话 ────→ 剥离 ticket 参数，直接进目标页
   ├─ 无会话 ──────→ POST /api/v1/auth/ticket-login {ticket}
   │                   ├─ 成功 → 写 token（与普通登录同一 localStorage 键）→ 进目标页
   │                   └─ 失败（过期/已用/无效）→ /login?redirect=原路径&expired=1
   └─ 兜底：用户手动登录后回跳 redirect（既有机制，不动）
```

### 2.3 四个组成

| # | 组成 | 一句话 |
|---|---|---|
| ① | 前端深链契约 | 各列表页声明接受的 query 参数，进入时初始化筛选 |
| ② | 后端 URL 构造器 | `web_links.py` 统一拼接；MCP 工具出参附 `web_url` |
| ③ | 免登票据 | 一次性 JWT 票据 + `ticket-login` 端点 + 守卫兑换 |
| ④ | Agent 话术 | SKILL.md 约定"给结论必附链接" |

A/B/C 三路线评估结论（2026-10-03 讨论）：**① + ③ 是通用底座**，链接（路线 A）是其最低兼容形态，覆盖对话 + 微信/邮件推送全场景；MCP Apps 内嵌（路线 B）依赖宿主支持且企业登录态在 iframe 中难走通，不采用。

## 3. ① 前端深链契约

### 3.1 参数约定

| 页面 | 路径与参数 | 行为 |
|---|---|---|
| 发票列表 | `/invoices?status=&keyword=&expense_type=&invoice_direction=&period=&invoice_id=` | 初始化 `filters`；`period=YYYY-MM/YYYY-Qn/YYYY` 设置周期锚点；`invoice_id` 载入后拉详情并打开抽屉 |
| 报销管理 | `/expenses?status=&claim_id=` | `claim_id` 经 `getClaim(id)` 打开详情抽屉 |
| 银行回单 | `/receipts?month=|quarter=|year=&receipt_id=` | 设置周期（复用现有 `periodParam` 形制）；`receipt_id` 载入后定位打开抽屉 |

参数值直接对应后端既有过滤参数（`status` 枚举值与 `InvoiceStatus` 一致，如 `pending_review`），不新造词汇。

### 3.2 关键规则：深链缺省周期 = 全部时间

> **理由**：Agent 场景多为"跨月的某一类票"（如待复核可能来自上月）。裸进列表页默认"本月"是浏览型默认值；深链是**定位型**，缺省应给全量，否则用户点开看到 0 条。

规则：URL 带任一业务参数（`status/keyword/expense_type/invoice_direction/invoice_id/period` 等）→ 未显式给 `period` 时 `periodType='all'`；不带任何参数正常进入 → 保持现状默认"本月"。Receipts 同理。

### 3.3 实现要点

- `InvoiceListView.vue`：`onMounted` 读 `useRoute().query` 初始化 `filters` / `periodType` / `anchor`，再调 `load()`；`invoice_id` 存在时额外调 `invoice_detail` 并 `showDetail()`。
- `ExpensesView.vue` / `ReceiptsView.vue`：同模式，改动量各约 10 行。
- 登录回跳：现有 `/login?redirect=` 机制直接复用，不改。

## 4. ② 后端 URL 构造器

### 4.1 配置新增（`config.py`）

```python
web_base_url: str = ""              # Web 后台对外地址，如 https://invoice.example.com；空=不产出链接
web_ticket_ttl_minutes: int = 480   # 免登票据有效期（分钟），0=关闭票据（链接仍产出，落登录页）
```

`web_base_url` 为空时全链路零行为变化（MCP 出参 `web_url=None`，Agent 不显示链接）。

### 4.2 新模块 `backend/src/invoicing/web_links.py`

```python
def enabled() -> bool: ...                     # web_base_url 非空
def issue_ticket(user_id: int) -> str | None  # TTL=0 返回 None；JWT{用途、jti、exp}
def web_link(path: str, *, user_id: int | None, **params) -> str | None
    # path 前缀白名单（/invoices /expenses /receipts /tasks /）
    # params 经 urlencode；user_id 且有 TTL → 附 ticket
```

所有 URL 只在此模块拼接，MCP 工具不各自拼字符串。

### 4.3 MCP 出参附挂

| 出参 | 新增字段 | 附挂值 |
|---|---|---|
| `InvoiceListResponse`（`invoice_list`） | `web_url: str \| None` | 列表页链接，**带调用方的同组筛选参数**（status/keyword 等原样回填） |
| `InvoiceOut`（`invoice_detail`） | `web_url: str \| None` | `/invoices?invoice_id=N` |
| `expense_list` 返回 | 响应级 `web_url`（工具改返回 `{items, web_url}`）或逐条附加二选一，实施时取改动小者 | `/expenses?claim_id=N` |
| `receipt_list` 返回 | 同上 | `/receipts?month=YYYY-MM` |

- **列表 items 不逐条出票**（20 条 = 20 张票，无谓膨胀）：列表给列表链接，单张链接由 `invoice_detail` 场景给。`InvoiceOut.web_url` 在列表 items 中为 `None`。
- 字段为普通可选字段（非 computed），沿用 `submitted_by_name` 的"服务层瞬态附挂"模式——构建需要用户上下文，computed_field 拿不到。
- 出参为**增字段**，对旧客户端向后兼容。

## 5. ③ 免登票据

### 5.1 票据设计

| 项 | 设计 |
|---|---|
| 形态 | JWT（复用 `jwt_secret` / 算法）：`{sub: user_id, purpose: "web_link", jti: uuid4, iat, exp}` |
| 有效期 | 默认 480 分钟（= 一个工作日会话，与 `jwt_expire_minutes` 对齐），可配；0=关闭 |
| 一次性 | 兑换时以 `jti` 抢占写表（唯一约束防重放） |
| 绑定 | 绑定用户；兑换后签发的是**该用户的普通会话 token**，不放大任何权限 |

### 5.2 数据表（新增，最小三列）

```
web_tickets(id/jti PK, user_id, expires_at, claimed_at)
```

- 签发票据**不写库**（只签 JWT）；兑换时 `INSERT jti`，主键冲突 = 已用过 → 401。
- 过期行惰性清理：每次兑换顺手 `DELETE WHERE expires_at < now()`（量极小，无需 cron）。
- alembic 迁移新增一版；`models/__init__.py` 注册 `WebTicket`。

### 5.3 兑换端点（`api/auth.py`）

```
POST /api/v1/auth/ticket-login  {ticket}
→ 200 TokenResponse（复用现有 schema）
→ 401「登录链接已失效，请重新登录」（过期/已用/用途不符/用户不存在，统一文案不泄漏细节）
```

- 校验链：JWT 解码 → `purpose=="web_link"` → jti 抢占 → 用户存在且非 `SUSPENDED`（与登录同一闸门）→ 签发 `create_access_token`。
- `must_change_password` 不在此拦：发 token 后路由守卫照常送改密页（与普通登录行为一致）。
- 审计：`action="LOGIN", channel="web_link"`，记录 IP；**ticket 原文不落审计**。

### 5.4 前端守卫（`router/index.ts` beforeEach 最前插入）

```ts
if (to.query.ticket) {
  if (!auth.token) {
    try { await auth.ticketLogin(String(to.query.ticket)); }
    catch { return { path: "/login", query: { redirect: 剥票后路径, expired: "1" } }; }
  }
  const { ticket: _drop, ...rest } = to.query;
  return { path: to.path, query: rest };   // 剥票再进：票据不留在地址栏/不被复制转发
}
```

- `LoginView.vue`：`query.expired` 存在时显示一行提示「登录链接已失效，请重新登录」（约 5 行改动）。
- `api/auth.ts` 新增 `ticketLogin(ticket)`。

### 5.5 安全边界

| 风险 | 处置 |
|---|---|
| 票据泄漏（聊天记录/转发） | 一次性 + TTL 上限 + 审计；未被点击前 TTL 内可被他人使用——接受（企业内网 + 可审计；如需更严再缩短 TTL） |
| 重放 | jti 主键抢占，第二次必失败 |
| Open redirect | 链接为站内路径导航（无 `next=外链` 参数），路由只认内部路由，天然免疫 |
| 票据被审计/日志记录 | 手写审计不落 ticket 原文；uvicorn 访问日志含 query——生产日志权限已在运维手册范围 |
| 离线部署 | 纯本地 JWT + DB 表，无外部依赖 ✓ |
| 权限 | 落地后全走既有 RBAC 与 `scoped_invoices` 数据隔离，票不放大权限 |

## 6. ④ Agent 侧话术（`docs/workbuddy-skill/SKILL.md` 增补）

```markdown
## 页面跳转（web_url）

- 工具返回含 `web_url` 字段时，在汇总结论后附一行 markdown 链接：
  「🔗 [去后台处理](web_url)」；列表场景给列表链接，单张场景给单张链接。
- 推送场景（日报/催办/巡检）必须附链接：财务从微信/邮件点开即直达已筛选页面。
- `web_url` 为空（未配置 web_base_url）时静默省略，不提示用户。
- 链接为一次性免登链接，不要自行改写或拼接参数。
```

内嵌 Web Agent（`agent/system_prompts.py`）同一条话术可 P1 再同步（用户本来就在网页里，票非必需）。

## 9. 验收标准

**单测**（`test/test_web_links.py`）：
- 未配置 `web_base_url` → `web_url is None`（零行为变化基线）
- 配置后拼接正确（含中文参数 urlencode、`period` 形制）
- 票据：签发→兑换成功；**二次兑换失败**；过期失败；`purpose` 不符失败；`SUSPENDED` 用户拒绝
- 列表出参带同组筛选参数回填

**前端**（`guard.spec.ts` 扩展）：
- 带 ticket 无会话 → 兑换后进目标页且 query 已剥票
- 带 ticket 有会话 → 不兑换、直接剥票进入
- 兑换失败 → `/login?redirect=…&expired=1`

**手工冒烟**：WorkBuddy 里「看看待复核」→ 回复含链接 → 未登录浏览器点开 → 直达 `/invoices?status=pending_review` 且列表非空（验证 §3.2 缺省全量规则）。

实施偏差（相对设计）：

1. `receipt_list` **P0 未附 web_url**（逐行出票 → 票据表写放大 + 响应膨胀；回单页深链留 P1 按需）
2. `expense_list` 逐条附 `web_url`（报销单基数小）；`invoice_list` 仅列表级单链接（20+ 行不逐条出票）
3. `/receipts` 深链额外支持 `quarter`/`year`（设计只列 `month`）
4. 顺带修复：axios 401 拦截器未豁免 `/auth/ticket-login`，兑换失败会硬跳 `/login` 冲掉 `redirect/expired` 参数（`web/src/api/client.ts`）
5. 组件挂载期 `route?.` 防御：既有组件测试裸挂载（无 router 插件），挂载期访问 `route.query` 会崩——`route?.query ?? {}` 保持该测试惯例，生产行为不变
