## 关键约束（决定了方案形态）

1. **`_require_owner_draft`（`workflow/expenses.py:86-90`）：仅报销单申请人本人可改草稿**——财务不能替他人在草稿里加凭证
2. **回单列表 API 为财务专属**（`api/receipts.py:111-118`，`require_role(*_FINANCE)`）——员工无法浏览回单
3. 推论：**「引用回单」入口只对财务有意义**（财务以自己为申请人建单：银行手续费/税费等公司级无票支出是财务的业务），员工侧入口 = 人工凭证

## T1 无票支出人工凭证录入 UI（ExpensesView）

- 事项行按钮组扩展：`加发票`（现有）+ **`无票凭证`**（`detailEditable` 时可见，所有申请人可用）
- 新 Modal 表单（字段对齐 `ItemAddVoucher`）：
  - 凭证类型：收款凭证 / 合同类 / 境外票据（`internal` 是系统自动生成，不进表单）
  - 金额（必填，>0）、费用类型（默认 other）、说明 note
  - `收款凭证`时显示：收款人姓名 + 身份证号（必填，后端要素校验），note 引导「支出项目」
- **提示前置**：提交后若返回 `deductible=false` → 立即 `message.warning(deductible_note)`
  （如「单次 800 元已超小额零星标准（500 元），需取得发票方可税前扣除」），不让问题拖到财务审批才发现
- 表单顶部提示行：显示小额零星标准（来自 `/expenses/config` 新增字段，见 T3）
- 明细表「税前扣除」列已有（绿标/橙标+tooltip），无需改

## T2 回单挂载入口（ExpensesView，财务限定）

- 事项行新增 **`引用回单`** 按钮，仅 `canFinance()` 可见（与回单列表 API 权限一致）
- 新 Modal：回单选号器——调用现有 `listReceipts`（默认本月，可切周期），列出 回单# / 交易日 / 对方 / 金额 / 交易性质；已被占用（`paired_invoice_id` 不适用，占用是报销侧）的回单由后端 `一单一报` 拦截，前端不预判
- 提交：client 新增 `addReceiptToClaim(claimId, entryId, { receipt_id, voucher_type?, expense_type?, note? })`——
  `voucher_type` 留空（后端按交易性质自动建议），表单可显示建议值说明但默认不覆盖
- 成功后刷新详情 + 列表

## T3 后端唯一改动：`/expenses/config` 增 `petty_cash_threshold`

`api/expenses.py:180-189` 现返回 `travel_allowance_daily_standard`；增加 `petty_cash_threshold`（读 `settings.expense_petty_cash_threshold`）。client 类型 + 表单提示用。

## T4 MCP 两工具（`mcp/tools.py`，套 `expense_add_invoices` 返回风格）

- `expense_add_receipt(claim_id, entry_id, receipt_id, voucher_type=None, expense_type="other", note=None)`
- `expense_add_voucher(claim_id, entry_id, voucher_type, amount, expense_type="other", note=None, payee_name=None, payee_id_no=None)`
- 均 `@requires("expense:write")`；返回 `{claim_id, claim_no, entry_id, total_amount, item: {...}}`；
  voucher 返回值带 `deductible` / `deductible_note`（Agent 可据此提示用户补要素或要发票）

## T5 测试

- 后端：MCP 两工具（成功 / 要素不全不可扣除 / 超 500 拦截提示 / 非申请人 422）；`/config` 新字段
- 前端：无票凭证 Modal（收款凭证必填校验、提交后 deductible=false 出 warning、非 editable 不显示按钮）；引用回单（仅财务可见、选择后调接口）
- 回归：全量 598 + 新增，前端 58 + 新增

## 明确不做

- 不改 `_require_owner_draft`（财务代员工挂凭证属权限模型变更，真实客户提出再立项）
- 不做附件上传（`attachment_url` 字段保留不用，合同类佐证资料仍走线下）
- 不做发票池/回单池合一的统一「加凭证」大弹窗（现有交互够用）

## 验收

- 财务角色：建单 → 加事项 → 引用回单 / 录收款凭证 → 提交 → 审批链路走通（浏览器实测）
- 员工角色：只有「无票凭证」入口，收款凭证填 800 元提交 → 立即提示不可扣除 + 原因
- 全量测试绿；MCP 侧 WorkBuddy 可调两新工具（真机项留 A4）
