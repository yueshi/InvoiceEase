发票易 · A4 真机冒烟操作单

2026-09-19 用途：PoC 检查清单 A4（上客户环境前的四项真机验证） 预估：1 天，需真实邮箱 / 企微群 / WorkBuddy 环境
执行口径：本机或预演服务器按序执行，每项记录「通过 / 不通过 + 现象」； 不通过项记入问题清单，修完重跑该项。全部通过后在《PoC 前检查清单》勾选 A4。

通用准备

  • 服务已启动（cd backend && uv run uvicorn invoicing.main:app --reload），后台可登录
  • 开发环境用 INVOICING_ENV=dev；如需按生产口径冒烟，先置 production 并确保弱默认已改（否则拒绝启动，见运维手册 §6）
  • 日志：backend/logs/；任务记录与告警：运维页 /ops（仅管理员）
  • 每项冒烟后到「审计日志」页确认有对应记录（A4 同时验证审计完整性）

A4-1 · 真实邮箱 IMAP 收票全链路

前置

  • 收票邮箱已开启 IMAP 并取得授权码（QQ 企业邮 / 163 / 飞书邮箱均可）
  • INVOICING_FERNET_KEY 已配置（未配置时保存邮箱凭据会被 400 拒绝）
  • 后台「系统配置 → 邮箱 → 新增」：类型 IMAP、主机/端口（如 imap.exmail.qq.com:993）、账号、授权码、主题关键词（如 发票,Invoice）

步骤

  1. 从外部邮箱向收票邮箱发 2 封邮件：① 附件为真实数电票 XML；② 附件为真实版式 PDF（主题含「发票」或正文含关键词）
  2. 等 ≤1 分钟（调度器每 60s 轮询）；着急可「运维 → 任务 → 手动执行 mailbox_poll」
  3. 打开「发票列表」，找到两张新票，逐张打开详情

预期结果（逐项勾）

  • ☐ 两张票出现在列表，状态推进至「待提交」（低置信度时「待复核」也算正常）
  • ☐ 详情字段完整：号码 / 开票日期 / 购销方 / 价税合计；XML 票解析来源显示 XML 直解
  • ☐ 详情有橙色「模拟模式」tag（验真披露，国税资质到位前属预期）
  • ☐ 原件已归档：backend/data/originals/tenant-default/ 下新增文件
  • ☐ 审计日志有 FETCH 记录；运维页任务记录 mailbox_poll 结果「成功」

可选加测（拒收合规路径）

  • 发一封带 图片（jpg/png）附件的邮件 → 若配置了 SMTP 回信，发件人应收到「仅接受原件」提示邮件；未配 SMTP 则跳过此项

失败排查

  • 任务记录里 mailbox_poll 的「错误」列；告警 mailbox.stalled（邮箱连续未成功收取）
  • 密码类错误 → 检查授权码；「无法解密」→ FERNET_KEY 与录入时不一致（见运维手册 §5）

A4-2 · 企微推送（告警通道 + 月报）

前置

  • 企微群 → 添加「群机器人」→ 复制 Webhook 地址
  • INVOICING_NOTIFY_WEBHOOK_URL=<地址> 写入 backend/.env，重启服务

步骤与预期

  1. 通道直发（与告警同一函数，验证 webhook 可用）： 
    cd backend
uv run python -c "from invoicing.notify import notify; notify('发票易冒烟测试：告警通道 ✅')"
    ☐ 企微群收到消息
  2. 月报真任务：「运维 → 任务 → 手动执行 monthly_health」（每月 1 日 09:00 自动跑，手动可即验） ☐ 群内收到月度健康报告（含验真模拟声明）
  3. ☐ 运维页任务记录里 monthly_health 结果「成功」

失败排查

  • 推送失败只记日志、不影响任务结果：看 backend/logs/ 中 invoicing.notify
  • 机器人被移出群 / URL 失效 → 重新生成

A4-3 · WorkBuddy 真机挂载（个人令牌）

前置

  • 后台「令牌管理」→ 签发新令牌：名称如「冒烟-张三」，权限按角色「一键填充」，90 天；当场复制明文（只显示一次）
  • WorkBuddy 的 mcp.json：URL http://<服务器IP>:8000/mcp，Header Authorization: Bearer <令牌明文>
安全收口（M1）变更提示：legacy 全局令牌（INVOICING_MCP_TOKEN）已默认关闭——必须使用个人令牌接入。

步骤与预期

  1. 让 Agent 调 invoice_list → ☐ 返回数据，且只含该令牌归属人可见的发票（员工看不到同事的与公共池）
  2. 让 Agent 调 invoice_ingest 导入一个本地 XML 原件 → ☐ 入库成功、列表可见
    注意 若配置了 INVOICING_WORKBUDDY_INBOX_DIR，文件必须在该目录内
  3. 让 Agent 调 expense_add_voucher（无票凭证，A2 新工具）→ ☐ 返回 deductible 与原因字段
  4. 审计页（安全 tab）→ ☐ 有 channel=mcp 记录，带 user_id + token_id（能回答“谁干的”）

失败排查

  • 401 → 令牌过期/被撤销/归属用户被暂停；「文件不在允许目录内」→ inbox_dir 未配或路径不对
  • 工具被拒 → 令牌 scope 不含对应权限（令牌管理页核对）

A4-4 · 员工上传 + 报销全流程（含 A2 两条新路径）

步骤与预期（员工账号）

  1. 发票列表 →「上传」一份 PDF/OFD/XML 原件 → ☐ 422 拦截图片（传图片试一次，应引导走邮箱）；原件上传成功并完成解析验真
  2. 报销管理 → 新建报销单（差旅）→ 添加事项 → ☐ 创建成功
  3. 事项行「加发票」→ 选上一步的票 → ☐ 加入成功、合计金额更新
  4. 事项行「无票凭证」→ 收款凭证：
    ① 金额 300 + 收款人姓名/身份证号 → ☐ 加入成功且明细「税前扣除」列绿标
    ② 金额 800 + 姓名/身份证号 → ☐ 提交后当场橙色提示「已超小额零星标准…需取得发票」，明细列橙标（悬停看原因）
  5. 提交审批 → ☐ 状态「待审批」

步骤与预期（财务账号）

  1. 财务建自己的报销单（注意：财务不能改员工的单——owner-only 是设计边界，不是 bug），加事项后点「引用回单」→ ☐ 弹窗列出未配对回单
  2. 选中一张税费类回单确认 → ☐ 凭证类型自动为「缴款书回单」（其他性质为「银行回单」）、金额取自回单
  3. 审批员工那张单（通过/驳回各试一次）→ ☐ 状态流转正确、驳回带理由
  4. 审计页（业务 tab）→ ☐ 有 EXPENSE_ADD_VOUCHER / EXPENSE_ADD_RECEIPT / EXPENSE_SUBMIT 等记录

失败排查

  • 「该回单已被占用」→ 一单一报，换一张；「回单金额缺失」→ 该回单解析未出金额，先补核对
  • 「无权操作他人的报销单」→ 用单子的申请人账号操作
