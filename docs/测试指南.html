三、服务启动与重启

# 后端（8000 标准端口；本机 8000 被 auditmind 占用时用 8001）
cd backend
INVOICING_MCP_TOKEN=wb-dev-token-2026 uv run uvicorn invoicing.main:app --host 127.0.0.1 --port 8001

# 前端（代理指向同端口）
cd web
VITE_API_TARGET=http://127.0.0.1:8001 npm run dev

改动解析代码后必须重启后端（无 --reload 时旧进程不感知新代码）。OCR 服务需以 --extra ocr 方式启动：uv run --extra ocr uvicorn ...。

四、五级解析路由速查

输入路由顺序parse_source
XML数电票 schema → rai XBRL（铁路客票）XML
PDF内嵌 XML（数电票/rai）→ 文本层规则 → OCR（渲染首页）→ 待复核PDF_XBRL / PDF_TEXT / PDF_OCR / PDF_UNSTRUCTURED
OFD内嵌 XML → Content.xml 文本规则 → OCR（Res 页面图）→ 待复核OFD_XBRL / OFD_TEXT / OFD_OCR / PDF_UNSTRUCTURED
图片（仅本地工具）PaddleOCR → 文本规则；OCR 未安装 → 报安装提示IMAGE_OCR

邮箱收取图片仍按合规拒收（FRD G-03），不受上述影响。

五、常见问题

  • OCR 识别失败/未安装：确认 uv sync --extra ocr 且服务以 --extra ocr 启动；macOS x86_64 锁定 paddleocr 2.x + paddle 2.6（Linux 可升 3.x）
  • 真实文件 FAIL：多为文本布局超出规则覆盖 → 落待复核（设计预期，宁缺毋滥）；把 error 文案发来可扩展规则
  • 测试环境：FakeOcrProvider 注入，uv run pytest 无需 ocr extra；装了 ocr extra 后测试仍绿（惰性加载 + 失败闩）
  • 前端 8000 端口：本机 8000 被其他进程占用时后端用 8001，VITE_API_TARGET 同步调整
