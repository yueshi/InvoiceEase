## 二、产品概述

### 2.1 产品定位

**发票易**是一款面向企业级市场的**电子发票自动化处理AI Agent产品**，以“邮箱自动获取 + OCR与大模型双引擎解析 + MCP服务集成 + 分角色权限管控”为核心能力，帮助企业实现电子发票从收取、识别、验真、查重到归档提交的全流程自动化。

产品名称“发票易”取“**易合规、易操作、易集成**”三重含义：
- **易合规**：严格遵循财政部电子凭证会计数据标准，只收OFD/PDF/XML原件
- **易操作**：绑定邮箱全自动，员工只需转发邮件，WorkBuddy对话即完成
- **易集成**：一套MCP服务，打通公司全员，一套系统管到底

### 2.2 背景与市场机会

2025年5月，财政部等九部门联合发布《关于推广应用电子凭证会计数据标准的通知》（财会〔2025〕9号），标志着我国会计信息化迈入标准化、全流程无纸化的新阶段。该标准以XML、XBRL等结构化数据为核心，覆盖电子凭证的接收、验签、解析、报销、入账、归档全流程。

然而，当前企业面临的现实困境依然突出：
- **接收难**：发票散落在员工邮箱、微信、手机相册，缺乏统一归集入口
- **识别难**：OFD/PDF/XML格式多样，人工录入效率低、错误率高
- **合规难**：拍照件、截图仍在流转，不符合电子会计凭证归档要求
- **管理难**：发票查重、验真依赖人工，重复报销风险高

发票易正是为解决上述痛点而生。

### 2.3 目标用户

| 用户角色 | 使用场景 | 核心诉求 |
|----------|---------|---------|
| **普通员工** | 收到发票后转发至指定邮箱，由Agent自动处理 | 省时省力，无需手动填单 |
| **财务专员** | 在Web后台查看、复核、批量提交发票 | 高效处理，减少重复劳动 |
| **财务主管** | 审批发票、导出报表、审计追溯 | 合规可控，数据透明 |
| **系统管理员** | 配置邮箱、管理用户、审计日志 | 易部署、易维护 |

### 2.4 核心价值主张

1. **合规第一**：严格执行“仅收原件”策略，从源头堵住不合规风险
2. **全自动流转**：邮箱收取 → 智能解析 → 自动验真查重 → 待提交列表，一气呵成
3. **AI驱动**：OCR + 大模型双引擎，解析准确率达95%以上
4. **开放集成**：基于MCP标准协议，无缝对接WorkBuddy等Agent平台
5. **一套系统**：一个公司、一套部署、全员使用、分权限管理


## 三、功能需求

### 3.1 模块一：发票获取（邮箱接入）

#### 3.1.1 功能描述
通过IMAP协议定时轮询企业邮箱，自动抓取邮件附件中的电子发票原件。

#### 3.1.2 详细需求

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| G-01 | 支持多IMAP邮箱接入（QQ邮箱、网易邮箱、企业邮箱等） | P0 |
| G-02 | 支持通过邮件主题关键词（如“发票”“Invoice”）自动筛选 | P0 |
| G-03 | **仅接受PDF、OFD、XML格式附件**，JPG/PNG等图片格式自动拒收并回复提示邮件 | P0 |
| G-04 | 支持ZIP压缩包自动解压并识别其中发票文件 | P1 |
| G-05 | 支持公网链接型发票（邮件正文含下载链接）的自动抓取 | P2 |
| G-06 | 支持定时轮询（默认每5-10分钟） | P0 |
| G-07 | 支持“已处理”邮件标记，避免重复收取 | P0 |
| G-08 | 支持Agently Mail等Agent专用邮箱服务接入 | P1 |

#### 3.1.3 异常处理
- 附件非发票文件 → 自动忽略并记录日志
- 附件为图片格式 → 自动回复：“检测到非标准格式，请发送该发票的OFD/PDF/XML源文件”
- 邮箱认证失败 → 通知管理员


### 3.2 模块二：发票解析（OCR + 大模型双引擎）

#### 3.2.1 功能描述
对获取的发票文件进行智能解析，提取结构化字段（发票代码、号码、金额、税额、购销方信息等）。

#### 3.2.2 解析策略（分级路由）

| 文件类型 | 解析方式 | 说明 |
|---------|---------|------|
| **XML格式数电发票** | 直接解析内嵌XML数据 | 最准最快，优先采用 |
| **内嵌XBRL的OFD/PDF** | 提取XBRL结构化数据 | 财政部标准格式 |
| **纯版式PDF（扫描件）** | OCR + 大模型识别 | 降级兜底方案 |
| **老旧扫描件/模糊件** | 多模态大模型（如Qwen-VL） | 视觉理解能力兜底 |

#### 3.2.3 解析字段标准

必提取字段（对应财政部电子凭证会计数据标准）：

```
{
  "invoice_code": "发票代码",
  "invoice_number": "发票号码",
  "issue_date": "开票日期",
  "amount_without_tax": "不含税金额",
  "tax_amount": "税额",
  "total_amount": "价税合计（小写）",
  "total_amount_cn": "价税合计（大写）",
  "seller_name": "销售方名称",
  "seller_tax_id": "销售方纳税人识别号",
  "buyer_name": "购买方名称",
  "buyer_tax_id": "购买方纳税人识别号",
  "invoice_type": "发票类型（专票/普票/数电票等）",
  "confidence_score": "置信度（0-1）",
  "parse_source": "解析来源（XML/OCR/VLM）"
}
```

#### 3.2.4 校验与质检

| 校验项 | 说明 | 处理方式 |
|--------|------|---------|
| **逻辑自洽** | 价税合计 = 不含税金额 + 税额 | 不一致则标记“待复核” |
| **大小写一致** | 大写金额与小写金额匹配 | 不一致则标记“待复核” |
| **置信度阈值** | 低于0.8的字段标注“需人工核对” | Web界面高亮提示 |

#### 3.2.5 Prompt工程要点

> *“你是一位资深财务审核员。请根据OCR文本/发票影像提取关键字段。规则：1. 严格区分‘购买方’与‘销售方’（根据‘名称’后括号内的‘销/购’字或坐标位置）；2. 金额提取阿拉伯数字原值，不得自行四舍五入；3. 输出严格遵循JSON Schema。”*


### 3.3 模块三：验真与查重

#### 3.3.1 验真
- 调用国税总局查验平台API（或第三方合规服务商如百望）
- 核验发票号码是否存在、状态是否正常（未被红冲/作废）
- 验真失败 → 标记“验真不通过”，进入人工复核队列

#### 3.3.2 查重
- 以“发票代码 + 发票号码”为唯一键，比对全公司历史数据库
- 发现重复 → **直接拦截**，提示：“该发票已于X月X日由XX提交，请勿重复报销”
- 查重范围：全部已处理发票（含已提交和处理中）

### 3.5 模块五：Web管理后台（分角色看板）

#### 3.5.1 功能模块

| 模块 | 功能 | 适用角色 |
|------|------|---------|
| **工作台** | 待处理数量、今日新增、月度统计 | 全部 |
| **发票列表** | 按时间/状态/金额筛选排序，支持搜索 | 全部（权限隔离） |
| **发票详情** | 原始文件预览 + 结构化数据展示 | 全部（权限隔离） |
| **人工复核** | 低置信度/验真失败/逻辑异常发票复核 | 财务专员+ |
| **批量提交** | 勾选发票 → 提交至金蝶/用友等财务系统 | 财务专员+ |
| **报表导出** | Excel台账导出 | 财务主管+ |
| **系统配置** | 邮箱配置、用户管理、角色分配 | 系统管理员 |
| **审计日志** | 全操作留痕，可追溯 | 系统管理员 |

#### 3.5.2 权限模型（RBAC）

| 角色 | 查看范围 | 操作权限 |
|------|---------|---------|
| **普通员工** | 仅本人相关发票 | 查看、补充说明 |
| **财务专员** | 全公司发票 | 查看、复核、批量提交 |
| **财务主管** | 全公司发票 | 查看、审批、导出报表 |
| **系统管理员** | 全公司发票 + 系统数据 | 全部操作 + 系统配置 |

#### 3.5.3 发票状态流转

```
收取中 → 已收取 → 解析中 → 解析完成 → 验真查重中 → 
  ├─ 验真通过 → 待提交 → 已提交 → 已归档
  ├─ 验真失败 → 待复核 → (人工确认后) → 待提交 / 驳回
  └─ 重复发票 → 已拦截（记录原因）
```


## 四、非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 单张发票解析时间 | XML/结构化解析 < 2秒；OCR+LLM < 10秒 |
| 邮箱轮询间隔 | 可配置（默认5分钟） |
| 并发处理能力 | 支持单日500+张发票处理 |
| Web后台响应时间 | 列表加载 < 2秒，详情加载 < 1秒 |

### 4.2 安全需求

- 所有发票数据加密存储（传输层TLS 1.3 + 存储层AES-256）
- 财务数据物理隔离，每个公司独立租户
- 操作审计日志完整记录（谁、何时、做了什么）
- 支持企业SSO/OAuth2.0身份认证（可选）

### 4.3 合规需求

- **严格遵循财会〔2025〕9号**：支持XML、XBRL等结构化数据的接收、验签、解析、报销、入账、归档全流程
- **仅接受原件**：PDF、OFD、XML格式，拍照/截图一律拒收
- **XML必须保存**：无论是否打印纸质发票，都必须保存含有数字签名的XML格式电子文件
- **验真合规**：所有发票须经国税查验平台核验
- **归档合规**：支持电子会计凭证长期保存和审计调阅

### 4.4 可用性需求

- 系统可用性 ≥ 99.5%
- 支持Docker容器化部署
- 支持离线部署（企业内部网络）

## 七、验收标准

### 7.1 功能验收

| 验收项 | 标准 |
|--------|------|
| 邮箱收取 | 正确识别并收取PDF/OFD/XML附件，拒收图片并回复提示 |
| 发票解析 | XML/结构化解析准确率100%，OCR+LLM准确率≥95% |
